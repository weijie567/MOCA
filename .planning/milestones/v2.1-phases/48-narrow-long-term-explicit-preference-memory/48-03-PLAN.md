<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ordinary chat -> long-term write | User text can request memory only through deterministic explicit preference phrases. |
| trusted context -> merchant scope | Chat-captured preference scope must come from trusted merchant scope, not LLM candidate slots. |
| admin API -> tenant/merchant preference | Admin save can affect broad scope and therefore needs stricter role and scope checks than review. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-48-06 | S/T | `preference_capture.py` phrase gate | mitigate | Deterministic phrase allowlist only; ordinary statements return no long-term candidate. |
| T-48-07 | E/I | merchant scope resolution | mitigate | Use trusted merchant scope; never tenant/user scope for chat-captured preferences. |
| T-48-08 | E | admin preference API | mitigate | Require `memory:write` scope and `admin` role; manager review role is insufficient. |
| T-48-09 | T | soft preference validation | mitigate | Reject hard-rule markers before candidate creation/API write. |
| T-48-10 | I/R | long-term service write | mitigate | Reuse existing PII, tombstone, source policy, and audit event paths. |
</threat_model>
