<objective>
Give the two new tables their write lifecycle so they are not empty machines: (1) a thread↔case
link writer with dedup invoked at an explicit linkage point (B3), and (2) a CWC write service that
resolves identity (44-02), writes the versioned row (44-02), emits a `case_working_context`
audit event (B4), and runs inside the isolated-session helper so a failure never poisons the caller.

Purpose: 44-RESEARCH §1.1 shows `append_message` drops case_id and there is no writer for a join
table — an association table with no writer stays empty. This plan defines exactly who writes the
link and when, and dedups it.
Output: thread_case_links repository + linkage hook, CWC write service with audit, and tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| run/staff action → thread_case_links | who may assert a thread touched a case |
| CWC write → caller transaction | a memory write failure must not roll back the caller's business txn |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-44-11 | Repudiation | thread_case_links writer | mitigate | explicit link_case linkage point + link_source enum records provenance of every link (B3) |
| T-44-12 | Tampering | duplicate links | mitigate | dedup select + uq_thread_case_links_active unique partial index |
| T-44-13 | Repudiation | untyped CWC write | mitigate | every CWC write emits memory_write_event(memory_type=case_working_context) (B4) |
| T-44-14 | Denial-of-service | caller txn poisoning | mitigate | write runs in isolated child session; failure rolls back child only |
| T-44-15 | Elevation | commitment auto-asserted as fact | mitigate | D-CWC-4: high-consequence entries kept claim/verified-marked and staff-correctable, not authoritative |
</threat_model>
