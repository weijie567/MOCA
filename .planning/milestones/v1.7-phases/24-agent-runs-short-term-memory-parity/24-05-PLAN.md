<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> create run | User can submit query/thread_id, but cannot submit trusted conversation IDs. |
| create run -> DB | Run row and user conversation message must commit atomically. |
| SSE claim -> graph config | Backend-resolved conversation identity enters LangGraph config. |
| graph config -> investigate | Tool persistence is enabled only by trusted `conversation_message_id`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-01 | Tampering/Repudiation | create/SSE retry path | mitigate | Create uses idempotent helper; pending claim still blocks duplicate graph execution. |
| T-24-02 | Repudiation | terminal finalizer | transfer | Final-response ordering is implemented in Plan 24-06. |
| T-24-03 | Spoofing/Tampering | SSE graph config | mitigate | Config IDs are resolved from DB after run claim; missing user message fails closed with `RUN_CONVERSATION_MESSAGE_MISSING`. |
| T-24-04 | Information Disclosure | conversation lookup | mitigate | Lookup uses authenticated `user`, `tenant_id`, `user_id`, `thread_id`, and run identity. |
| T-24-05 | Elevation of Privilege/Tampering | tool summaries | mitigate | Tool persistence still flows through `investigate` and `ConversationService.append_tool_result`; no raw prompt builder is added. |
| T-24-06 | Repudiation | non-completed statuses | transfer | Completed-only terminal semantics are implemented in Plans 24-06 and 24-07. |
</threat_model>
