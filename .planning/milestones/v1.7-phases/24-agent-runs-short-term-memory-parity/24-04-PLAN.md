<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API/finalizer -> ConversationService | Later routes can request user/assistant rows without calculating message indexes or bypassing safety validation. |
| Thread summary builder -> repository | Derived summary crosses into durable storage only after source-end idempotency lookup. |
| Tool summaries -> prompt context | Tool result material remains projected through `ToolResultPromptSummary` and sanitizers. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-01 | Tampering/Repudiation | `append_or_get_*_message_for_run`, summary lookup | mitigate | Helpers read existing rows before insert and rely on Plan 24-03 DB uniqueness under race/retry. |
| T-24-02 | Repudiation | summary persistence | mitigate | Summary helper returns explicit existing/created result; no duplicate success rows. |
| T-24-03 | Spoofing/Tampering | conversation IDs | mitigate | Repository lookups scope by tenant/user/thread/run/role; later API passes backend-trusted IDs only. |
| T-24-04 | Information Disclosure | repository scoped reads | mitigate | Every helper scopes by `tenant_id`, `user_id`, `thread_id`, and active non-deleted rows. |
| T-24-05 | Elevation of Privilege/Tampering | message metadata and summary content | mitigate | Helpers reuse `validate_safe_message_payload`; summaries use existing sanitizer and prompt-safe tool summaries. |
| T-24-06 | Repudiation | assistant/summary helpers | mitigate | Only later completed finalizer should call assistant/summary helpers; helpers themselves are idempotent and status-neutral. |
</threat_model>
