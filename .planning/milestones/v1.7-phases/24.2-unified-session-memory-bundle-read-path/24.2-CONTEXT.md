# Phase 24.2: Unified Session Memory Bundle Read Path - Context

**Gathered:** 2026-06-21
**Status:** Ready for planning
**Source:** Memory architecture review and current MOCA source read

<domain>
## Phase Boundary

Phase 24.2 收口 session 级短期记忆读路径。当前 `SessionMemoryBundle` facade 已存在，但 graph prompt 节点仍分散调用 `ConversationService.load_prompt_context(...)`，slot continuity 仍由 `session_memory_load` 单独写入 `state["session_memory"]`。

本 phase 的目标是让上层 prompt context 读取统一经过 `SessionMemoryBundle`，同时保留既有 `session_memory` slot continuity 状态字段，避免破坏 Phase 24 已完成的 slot routing、memory write CAS、authority boundary 和 API/SSE 行为。
</domain>

<decisions>
## Implementation Decisions

### Scope

- `SessionMemoryBundle` 是当前 run/thread 的 prompt-safe session read model。
- `SessionMemoryView` 继续作为 slot continuity 兼容对象；新代码优先通过 `slot_continuity` 访问。
- `session_memory_load` 可以附带生成 `session_memory_bundle`，但必须继续返回旧 `session_memory` 字段。
- Prompt 节点读取 rolling summary、recent messages、tool summaries 时优先从 `state["session_memory_bundle"]` 投影，缺失时再通过 bundle service fallback。
- 不改数据库 schema，不改外部 API payload，不把 memory 升级为 policy evidence、business fact authority、action authority 或 replay truth。

### Safety

- Bundle 投影只允许 prompt-safe 字段。
- `raw_payload`、`private_reasoning`、`approval_authority_body`、`debug_trace`、secret 类字段不得进入 prompt context。
- 现有 session slot trust metadata 校验继续由 routing 层负责。
</decisions>
