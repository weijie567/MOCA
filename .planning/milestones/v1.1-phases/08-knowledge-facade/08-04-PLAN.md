# 08-04 PLAN: State + Node + Consumer Migration to KnowledgeService

<objective>
Switch the runtime path from the direct `search_policy` call to `PolicyKnowledgeService.search(...)` and migrate state/consumers to canonical `EvidenceRefV1` (D-A3, D-A4, D-B4, D-C2, D-D2). Specifically:

1. Migrate `src/agent/state.py` `EvidenceRef` TypedDict to the full EvidenceRefV1 field set.
2. Change the `evidence_refs` merge key from `(doc_key, chunk_id)` to `evidence_id` in `retrieve_policy_evidence._merge_evidence_refs`.
3. Switch `retrieve_policy_evidence` to build a `KnowledgeContext` (effective_at = run start), call the facade, and map `knowledge_search_result.v2` into AgentState.
4. Update `generate_recommendation` to emit structured material claims carrying `evidence_id`, run the new `validate_membership` (08-03), and keep merged refs consistent.
5. Keep `final_response` citation rendering working against migrated refs.
6. **(B2 — Codex review)** Extend `assess_risk_and_approval` so it suppresses any proposed action for ALL no-action draft states — `citation_invalid` and `retrieval_error`, not just `insufficient_evidence`. Today only `insufficient_evidence` short-circuits, so a failed-membership (`citation_invalid`) or retrieval-error draft can still produce a `manual_review` proposed action, contradicting the "failed membership / no evidence → no deterministic action" gate.
7. **(run-start `effective_at`)** Persist the run-start timestamp in `receive_request` (new `run_started_at` state field) so the retrieval node uses the true run start, not node-entry wall-clock.

This is the only Phase 8 plan that changes runtime behavior. It must preserve existing strong/partial/no_evidence routing and the insufficient-evidence / retrieval-error drafts. Rollback is git revert (the adapter + legacy `search_policy` remain intact). No schema migration, no graph topology change.
</objective>
