<architecture_alignment>
## Architecture Alignment

Canonical owner package: `src/replay` owns replay schemas and V3 contract shape. Schema owner remains `src/db/models.py` plus Alembic migration `010_replay_event_v3.py`.

Expansion strategy:
- Keep existing minimal rows as `schema_version="minimal_event_envelope.v1"`.
- New Phase 15 replay rows use `schema_version="replay_event.v3"`.
- Add nullable V3 columns where old rows cannot supply facts: `parent_operation_id`, `attempt`, `version`, `node_name`, `approval_id`, `draft_id`, `tool_call_id`, `evidence_refs_json`, `error_json`, `archived_at`, `retention_until`, and `deleted_at`.
- Do not add Phase 17 `execution_id` unless a referenced table already exists. If no table exists, leave `execution_id` deferred to Phase 17 and record this in migration tests.
- Preserve existing `actor`, `resource_refs`, and `redacted_payload` storage names if the ORM already uses those names; `src/replay/schemas.py` may project contract names without a physical rename.

Required DB constraints/indexes:
- Check `schema_version in ('minimal_event_envelope.v1', 'replay_event.v3')`.
- Check `event_type` belongs to the consolidated Phase 15 replay enum from `src/replay/validators.py`.
- Check `sequence > 0`.
- Check `attempt is null or attempt > 0`.
- Add indexes named or clearly equivalent to `ix_agent_trace_events_tenant_run_sequence`, `ix_agent_trace_events_tenant_run_operation`, `ix_agent_trace_events_tenant_occurred_at`, and `ix_agent_trace_events_event_type_occurred_at`.
- Keep existing unique `(run_id, sequence)` backstop.
</architecture_alignment>
