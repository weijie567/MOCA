<architecture_alignment>
## Architecture Alignment

`RunLifecycleService` owns lifecycle replay events and finalizer calls. `src/agent/trace.py` is the lifecycle-aware persistence seam for `write_agent_run()` and `update_agent_run_status()`. API routers remain callers only. Action draft replay safety stays in Plans 15-02 and 15-06; this plan does not modify action draft service code.

Required lifecycle statuses:
- `running`
- `interrupted`
- `resumed`
- `completed`
- `rejected`
- `expired`
- `error`
- `cancelled`

Important semantics:
- A normal run may emit `run_status_changed` from `running` to `completed`.
- An approval request interruption emits `run_status_changed` with `status="interrupted"`.
- An accepted approval resume emits decision/resume events and continues to terminal status in the same run after post-resume processing.
- A `respond`/needs-info decision records clarification refs and remains `interrupted`, not `completed`.
- Rejected, expired, cancelled, and error runs preserve partial timeline plus safe terminal status.
- Do not enable active SLA scanning in Phase 15; only verify disabled-by-default behavior.
</architecture_alignment>
