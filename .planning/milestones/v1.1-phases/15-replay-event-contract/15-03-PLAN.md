<architecture_alignment>
## Architecture Alignment

Operation pairing belongs to `src/replay`, not routers and not individual graph nodes. Writers supply `operation_id`, `parent_operation_id`, and `attempt`; the replay service validates the operation state before append or during explicit validator calls.

Rules:
- Event families ending in `_started` start an operation.
- Event families ending in `_completed`, `_failed`, `_unknown`, `_expired`, `_cancelled`, or terminal lifecycle statuses close an operation where applicable.
- A terminal event must not exist twice for the same `(run_id, operation_id)`.
- Retry attempts must use a new `operation_id`, a non-null valid `parent_operation_id`, and `attempt > parent_attempt`.
- Bounded investigate loop tool/RAG child events preserve `redacted_payload["iteration"]`.
- Old/minimal rows without enough facts are projected as `pairing_status="unresolved"` and are not rewritten.
</architecture_alignment>
