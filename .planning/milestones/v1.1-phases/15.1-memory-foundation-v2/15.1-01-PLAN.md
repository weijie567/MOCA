<architecture_alignment>
## Architecture Alignment

Canonical owner package: `src/conversation` owns conversation-log append/read services. Schema owner is `src/db/models.py` plus Alembic revision `011_memory_foundation_v2.py`.

Old-path quarantine/deletion strategy:
- Keep `AgentRun.input_query` and `AgentRun.final_response` as run-level summaries for compatibility.
- Do not delete `AgentStep`, `AgentTraceEvent`, `session_memories`, approval, action, or replay code.
- New code should read conversation facts through `ConversationService`, not by reconstructing messages from `AgentRun` and `AgentStep`.

Forbidden new imports/references:
- `src/conversation` must not import business repositories as fact authority.
- `src/conversation` must not import policy KB internals as evidence authority.
- Conversation rows must not be used as approval/action authorization.
- No `case_memories`, memory tombstone, vector search, or case precedent retrieval code in this phase.

Boundary tests required:
- Tenant/thread isolation for conversation append/read.
- Raw prompt/private reasoning/raw tool payload exclusion tests.
- Migration/model parity tests.
- Regression check that replay redaction remains owned by `src/replay`.

Migration rollout protocol:
- Schema owner: `src/db/models.py` and `src/db/migrations/versions/011_memory_foundation_v2.py`.
- Read-switch/fallback owner: `src/conversation/service.py` and `src/api/routers/agent.py`. The schema migration is additive and does not move existing readers during the migration task, so no runtime read-switch is needed before append wiring. Fallback is to disable or revert Phase 15.1 conversation append/load wiring while existing `AgentRun`, `AgentStep`, `agent_trace_events`, `session_memories`, approval/action tables, and replay remain the canonical operational paths.
- Rollback owner: Alembic `downgrade()` in `011_memory_foundation_v2.py`, dropping only Phase 15.1 tables/indexes/constraints in reverse dependency order. Rollback command: `UV_CACHE_DIR=/tmp/uv-cache uv run alembic downgrade 010_replay_event_v3`.
- Rollout verification: run upgrade, focused schema tests, and a disposable-database downgrade/upgrade round trip before downstream plans start. Do not run downgrade against a shared or data-bearing developer database.

Phase non-overlap:
- Phase 13 owns approval/snapshot authority and remains the source for approval correctness.
- Phase 14 owns action draft/demo outcome authority and remains the source for draft correctness.
- Phase 15 owns replay events and remains the redacted audit timeline.
- Phase 15.1 owns conversation facts and prompt-safe references.
- Phase 16 owns long-term/case memory, tombstones, review workflow, and retrieval.
- Phase 17 owns external execution/outbox/reconciliation/compensation.
</architecture_alignment>
