<interfaces>
Redis acceptance rules if explicit approval is given:
- Key pattern: `session:{tenant_id}:{user_id}:{thread_id}`.
- TTL is mandatory and no longer than the session memory TTL.
- Cache value is a derived loaded view reconstructable from `session_memories`.
- Cache miss, stale version, JSON decode error, timeout, or Redis unavailable falls back to PostgreSQL.
- Writes commit through PostgreSQL CAS before any cache update is trusted.
- Redis is never authoritative and never owns schema/migration truth.
- Redis loss must not affect correctness, auditability, replay, approval/action safety, or deterministic merge.

```markdown
# Phase 12 Redis Evaluation

Revisit trigger: measured session memory read latency or DB load exceeds agreed threshold after production-like tests.
Required future tests: cache miss, stale version, Redis unavailable, invalid JSON, post-CAS cache refresh, no Redis-only correctness.
```
