<interfaces>
Authoritative table shape from `docs/contract-spec.md` Section 18.1:
- `session_memories.id uuid primary key`
- `tenant_id uuid not null references tenants(id)`
- `user_id uuid not null references users(id)`
- `thread_id varchar not null`
- `schema_version varchar not null default 'session_memory.v2'`
- `active_slots_json jsonb not null default '{}'`
- `session_summary text null`
- `unresolved_questions_json jsonb not null default '[]'`
- `last_intent varchar null`
- `last_business_context_refs_json jsonb not null default '{}'`
- `last_run_id uuid null references agent_runs(id)`
- `version int not null default 1`
- `expires_at timestamptz null`
- timestamps and `deleted_at timestamptz null`

Active uniqueness: unique partial index on `(tenant_id, user_id, thread_id)` where `deleted_at IS NULL`.

Slot envelope:
```json
{
  "schema_version": "session_slots.v1",
  "slots": {
    "order_id": {
      "value": "ORD-1001",
      "source": "explicit_user",
      "source_run_id": "uuid",
      "updated_at": "2026-06-14T00:00:00Z",
      "expires_at": "2026-06-14T00:30:00Z",
      "compatible_intents": ["order_status_inquiry", "refund_troubleshooting"]
    }
  }
}
```

  Merge precedence: current-turn explicit validated slots, then compatible non-expired existing session slots, then no inherited value.

  Field-level CAS merge policy:
  - `active_slots_json`: merge by slot key. Current-turn explicit validated slots override compatible non-expired existing slots. Conflicting current-turn explicit values from different runs return conflict/fallback with `reason_code="explicit_slot_conflict"`.
  - `unresolved_questions_json`: normalize and de-duplicate by missing slot group/question text; preserve existing unresolved questions plus current unresolved questions.
  - `last_business_context_refs_json`: merge non-conflicting keys. If the same key has different values from concurrent runs and cannot be tied to the current explicit slot, return conflict/fallback rather than overwriting silently.
  - `session_summary`: if only one side has a safe summary, keep it; if both have distinct safe summaries and the combined deterministic summary fits the configured cap, preserve both in deterministic order. If preserving both would exceed the cap, skip the summary update or return conflict/fallback with an observable reason; never silently replace a concurrent summary.
  - `last_intent`: current candidate may replace the stored value on a non-conflicting write. On CAS retry with a different latest `last_intent`, preserve the latest value unless the service can attach an observable merge warning/reason; never present this scalar as proof of policy, risk, approval, or action state.
  - Expired active row write policy: an active row whose `expires_at` has passed must be handled by CAS reuse or transactionally soft-deleted before insert. A fresh write must not fail solely because the expired row still satisfies the partial unique index.

  Forbidden: Redis correctness path, raw dict service boundary, model/LLM writes directly to memory, session memory as `EvidenceRefV1`.

| Boundary | Description |
|----------|-------------|
| database row -> inherited slot | Stored JSON must be validated before it can become router-visible slot metadata. |
