# Milestone v1.3: RAG Hybrid Retrieval

**Status:** SHIPPED 2026-06-18
**Phases:** 20
**Total Plans:** 1

## Overview

v1.3 upgraded MOCA's policy retrieval path from pgvector-only retrieval plus lightweight lexical rerank into a minimal production hybrid retrieval backend on PostgreSQL.

The milestone combines pgvector semantic retrieval, PostgreSQL full-text sparse retrieval, and pg_trgm fuzzy retrieval with Reciprocal Rank Fusion, while preserving `PolicyKnowledgeService`, canonical `EvidenceRefV1`, citation identity, and the Tool System boundary for business facts.

## Milestone Summary

### Key Decisions

- Keep hybrid retrieval behind `PolicyKnowledgeService` rather than adding a full external `SearchBackend` abstraction in v1.3.
- Persist retrieval-only `PolicyChunk.search_text` separately from canonical citation content.
- Use application-tokenized Chinese/domain search text with PostgreSQL `simple` full-text search.
- Use RRF for dense/sparse/fuzzy ordering while keeping `EvidenceRefV1.score` and `KnowledgeSearchResult.best_score` as normalized 0-1 confidence values.
- Keep hybrid trace fields internal/eval-only and excluded from API serialization and `EvidenceRefV1`.

### Issues Resolved

- Added migration-backed `search_text`, generated `search_vector`, GIN full-text index, pg_trgm index, and retrieval-scope index.
- Added deterministic tokenizer/domain-term handling for refund/support terms.
- Added sparse/fuzzy repository channels with tenant, doc type, risk level, and effective-date filters.
- Added RRF fusion and diagnostics without changing the policy evidence contract.
- Completed UAT with 7/7 checks passing and security verification with 5/5 threats closed.

### Issues Deferred

- Phase 21: RAG Production Ingestion + OCR owns OCR/parser abstraction, `DocumentBlock`, page/bbox/cell citation, table-aware chunking, OCR confidence, and parser trace.
- Phase 22: RAG Context Builder + Hallucination Control owns `MaterialClaim`, semantic support verifier, conflict/freshness routing, refusal/manual-review policy, and faithfulness/citation eval.
- Phase 23: RAG Reranker + Query Rewrite owns query rewrite, reranker interface, optional cross-encoder/external rerank API, full ranking explanation, retrieval ablation eval, and latency budget.
- Phase RAG-5: Optional External Search Backend owns Vespa/OpenSearch shadow testing and full external `SearchBackend` if PostgreSQL hybrid no longer fits scale or ranking-profile needs.
- Post-Phase 17 Policy Scope owns tenant-over-global global/default policy fallback.
