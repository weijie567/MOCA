## Pattern Assignments

### `docs/contract-spec.md` (contract, transform)

**Analog:** `docs/contract-spec.md`

**Contract target pattern** (lines 70-103):
```markdown
Role registry:
merchant_bound_roles = {"support", "manager", "merchant"}
platform_admin_roles = {"admin"}

- `support` / `manager` / legacy `merchant`:
  - `user.merchant_id` exists -> merchant_scope has that merchant id.
  - missing `user.merchant_id` -> empty merchant scope, deny-all for business data.
- `admin` -> wildcard merchant scope.
- non-admin wildcard `server_merchant_scope` must be rejected, not silently narrowed.
```

**Interim guard pattern** (lines 105-120):
```markdown
- Cross-tenant resources return 404.
- Same-tenant out-of-merchant-scope business resources return 403.
- AgentRun/trace access is owner/admin only until later target merchant binding.
- Manager approval list/get/decide is admin-only for Phase 29.5.
- Wildcard merchant scope must not be constructed outside TrustedContextFactory / trusted system context.
```

**Policy-only split pattern** (lines 122-132):
```markdown
Tenant public policy retrieval does not require wildcard merchant scope and must not be denied solely because
a merchant-bound user has merchant_scope=[merchant_id] or merchant_scope=[].
The same empty scope remains deny-all for business data and merchant-specific/business-scoped policy filters.
```
