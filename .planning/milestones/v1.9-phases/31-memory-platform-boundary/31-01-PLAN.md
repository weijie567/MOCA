<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| memory DTO -> authority DTO | Contextual memory refs cross into evidence/business/approval/action/replay validators and must be rejected. |
| session context -> prompt context | Same-thread summaries, messages, tool summaries, and slots become prompt context but not authority. |
| test database -> DB-backed pytest | Shared `moca_test` metadata setup must not run in parallel. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-cross-merchant | I | session/reviewed memory prompt context | mitigate | RED tests require contextual refs to carry tenant/user/thread/scope metadata and later plans add trusted-scope fail-closed behavior. |
| T-31-authority-forgery | S/T | `SessionContextRef`, `ReviewedMemoryRef`, verifier tests | mitigate | Tests require `authority_class="contextual_only"` and explicit rejection as `EvidenceRefV1`, `BusinessFactRefV1`, approval evidence, action refs, `MaterialClaim.business_fact_refs`, and `ReplayEventV3`. |
| T-31-pii-leakage | I | memory prompt refs/status refs | mitigate | Tests require prompt-facing memory refs/status refs to be bounded contextual metadata; Plan 31-02 and 31-05 add PII retrieval filter tests. |
| T-31-tombstone-revival | T/R | reviewed memory lifecycle | mitigate | This plan references the contextual-only ref contract; Plan 31-02 adds RED lifecycle tests and Plan 31-06 implements write-decision status. |
| T-31-replay-confusion | R/T | memory status refs vs replay truth | mitigate | Tests require memory status refs to be rejected as `ReplayEventV3`; Phase 35 owns replay-authoritative event coverage. |
| T-31-write-rollback | D/T | memory side-effect write policy | mitigate | `MemoryWriteDecisionV2` RED contract requires `status`, `reason_code`, and `fallback_reason`; Plan 31-06 preserves isolated/no-rollback write behavior. |
</threat_model>
