# Phase 25 Plan 01: Intent Routing Safety Hardening

<objective>
Implement the full v1.8 intent routing safety hardening slice: auditable raw-to-effective classification traces, deterministic risk tiers, workflow-state-first handling for pending clarification answers, slot provenance/invalidation, and focused regression coverage.
</objective>

<must_haves>
- Raw LLM classification remains visible but advisory; effective classification drives business state.
- `RiskTier` is deterministic and derived from intent, requested operation, role, channel, and routing hints.
- `HIGH_RISK_INTENTS` remains available for current callers while new risk-tier behavior is tested.
- Pending required-slot clarification can consume short identifier replies without full conversation-history classification.
- Ambiguous approval/continue replies fail closed in ordinary chat unless a trusted pending flow explicitly allows them.
- Inherited slots with invalidation markers cannot satisfy required slot completeness.
- Tests cover trace, risk tier, workflow-state-first, slot invalidation, and approval/action boundary regressions.
</must_haves>

<threat_model>
## Threat Model

| Threat | Severity | Mitigation |
|--------|----------|------------|
| User says "approve APR-1" in ordinary chat and bypasses approval channel | high | `approval_chat_not_trusted` maps to `forbidden_in_chat`; route remains `clarification_gate`; forbidden approval/action fields stay blocked. |
| LLM raw classification mislabels direct execution as read-only | high | Deterministic pre-route and policy overrides populate effective classification and risk tier; business state uses effective classification. |
| Short reply "同意" or "继续吧" executes a stale action | high | Active-flow resolver only answers trusted pending slot flows; ambiguous short approvals without trusted flow route to clarification. |
| Stale inherited order/refund/ticket slot is reused after user negation | high | Slot invalidation metadata blocks inherited values from completeness resolution and routes to clarification or current-turn replacement. |
| Trace leaks raw private prompts or authority bodies | medium | Classification trace stores structured schema outputs and reason codes only, not prompt text, tool raw payloads, or private reasoning. |
</threat_model>

  Add a deterministic helper in `classify_intent.py` or `intent_policy.py` that detects identifier-only or identifier-like answers: `ORD-...`, `RF-...`, `TKT-...`, `订单...`, `退款单...`, `工单...`.
  If `active_flow_state.kind == "pending_required_slot"` and the current query is an identifier-like answer, skip LLM classification and return the previous effective intent/operation/required slots with routing hint `workflow_state_resolution: "answered_pending_required_slot"` and risk tier from `resolve_risk_tier`.
  If query is ambiguous short approval/continue text such as `继续吧`, `同意`, `就按上面的处理`, and no trusted pending slot answer applies, route to clarification by setting `primary_intent: "unsupported"`, `requested_operation: "advise"`, `routing_hints.clarification_reason: "unsupported_or_ambiguous"`, and risk tier `forbidden_in_chat` only when approval/action wording is present.
