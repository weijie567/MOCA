<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| previous answer context to new user turn | Stored safe metadata influences follow-up query derivation. |
| follow-up text to derived BusinessQuerySpec | Untrusted follow-up text selects only allowed fields, cursor actions, resource ids, or time answers. |
| derived spec to ToolPlatform | Derived queries must be revalidated by schema, ToolPolicy, and BusinessFactService. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-62-13 | Information Disclosure | `last_answer_context` | mitigate | Store safe refs, fields, cursor capability, and summaries only; tests reject raw rows and hidden scope internals. |
| T-62-14 | Spoofing | same-thread follow-up state | mitigate | Use thread/session state only; cross-thread drilldown cannot access stale context. |
| T-62-15 | Tampering | derived drilldown spec | mitigate | Derive specs through registry allowlists and revalidate through BusinessQuerySpec and BusinessFactService. |
| T-62-16 | Information Disclosure | cursor and field drilldown | mitigate | Cursor and field requests are structured expected-slot types; raw cursor tokens and unallowlisted fields are rejected. |
</threat_model>
