<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller to BusinessQuerySpec | Untrusted tool args cross into strict schema validation. |
| JWT/trusted context to tool permission | Authenticated scopes become ToolCallContext permissions; user text must not grant permission. |
| ToolCatalog/ToolPolicy to runtime | ToolPlatform must reject malformed or unauthorized specs before BusinessFactService execution. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-62-04 | Tampering | `BusinessQuerySpec` | mitigate | Strict Pydantic models with `extra="forbid"` reject authority fields, arbitrary filters, raw SQL, raw cursor strings, unknown operations/resources, and oversized limits. |
| T-62-05 | Elevation of Privilege | `TrustedContextFactory` and ToolPolicy | mitigate | Only trusted auth scopes map to `tool:business_query`; `merchant_id` remains a filter and cannot widen merchant scope. |
| T-62-06 | Information Disclosure | `query_business_metric` compatibility path | mitigate | Compatibility input maps into `BusinessQuerySpec`; it does not bypass no-existence-leak or descriptor compatibility gates. |
| T-62-07 | Tampering | business read operation taxonomy | mitigate | Contract and schema tests exclude draft and execute from business-query operations per D-62-17. |
</threat_model>
