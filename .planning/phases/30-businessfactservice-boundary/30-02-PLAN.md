<threat_model>
## Trust Boundaries

| Boundary | Description |
| --- | --- |
| ToolRuntime -> BusinessToolExecutor | Runtime authorization is complete; domain ownership proof begins after dispatch. |
| BusinessFactService -> ToolResultV2 wrapper | Domain result becomes graph/tool envelope; fail-closed statuses must not gain data or refs. |
| ToolPolicyEngine marker -> BusinessFactService proof | `requires_domain_scope_check` metadata must be resolved by domain proof before refs are emitted. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- |
| T-30-05 | Elevation of Privilege | `BusinessToolExecutor` | mitigate | Executor imports/delegates to BusinessFactService only; raw repositories/integrations are forbidden in the executor. |
| T-30-06 | Information Disclosure | `BusinessFactResultV1` to `ToolResultV2` wrapper | mitigate | Denied/stale/unavailable/unsupported wrappers set `data=None`, `business_fact_refs=[]`, generic safe errors. |
| T-30-07 | Tampering | `requires_domain_scope_check` marker | mitigate | ToolPlatform chain tests assert marker presence and service-enforced denial before refs/facts. |
| T-30-08 | Spoofing / Elevation of Privilege | ToolPlatform vs BusinessFactService responsibility split | mitigate | Keep caller/permission/schema/side-effect/idempotency gates in ToolRuntime and domain proof in service; tests cover both. |
</threat_model>
