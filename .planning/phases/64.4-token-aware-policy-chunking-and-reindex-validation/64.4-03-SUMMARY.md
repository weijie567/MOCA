## Decisions Made

- Provider usage is retained at the only granularity actually reported by the API request. `EmbeddingBatchResultV1` has request records, not per-input token records.
- A batch aggregate is truthful only if every constituent request supplies complete prompt and total usage. Otherwise both aggregate fields are `None` and status is `unavailable`.
- Offline tokenizer parity is evaluated against provider `prompt_tokens`; `total_tokens` is preserved for accounting but not treated as per-input evidence or an undocumented tokenizer definition.
- A parity report can be `passed` only from exact ten-single plus ten-input-aggregate live observations. Contract tests deliberately exercise red/unavailable paths and the passed-only gate without mocking live provider success.
- Fresh selection requires exact configuration fingerprint, provider, model, dimensions, tokenizer/assembly versions, fixture hash, submitted final-content hash, UUID capture identity and maximum age.
