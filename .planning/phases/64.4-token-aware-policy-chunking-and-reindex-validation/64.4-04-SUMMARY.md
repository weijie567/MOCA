## Accomplishments

- Added `IngestionAssemblyMode`, `PolicyInputAssembler`, `CharacterCompatibilityAssembler` and the shared `assemble_policy_embedding_inputs` entry point. Ordinary ingestion remains character-compatible by default; token-aware ingestion is explicit and fail-closed.
- Preserved the incumbent character-mode provider bytes while returning the same frozen `PolicyEmbeddingInputV1` shape as token mode, with the Plan 01 counter's real token count, exact input hash and a canonical `character_compatibility.v1` configuration fingerprint.
- Changed production embedding to submit `dto.embedding_input` exactly and project citation/search/provenance from the DTO without persisting the new audit fields before Plan 05.
- Migrated CLI dry-run to the production parser plus token assembler and proved it creates neither provider nor database clients and performs no writes.
- Migrated golden corpus validation to the production manifest/parser/shared assembler and exposed the same typed assembler seam through the real Phase64.3 retrieval-parity ingestion constructor.
- Added AST and source-contract guards that reject direct production `chunk_markdown`, unauthorized `chunk_blocks`, duplicate budget loops/envelope renderers, unnamed compatibility construction and reconstructed authoritative final strings.

## Decisions Made

- Ordinary production remains byte-compatible through `CharacterCompatibilityAssembler` until Plan 06. The presence of token mode in this plan does not activate it implicitly or mix it into the current corpus.
- Both assemblers return `PolicyEmbeddingInputV1`; character compatibility is a measurable baseline, not an untyped bypass, and therefore carries an actual pinned token count/hash/config identity for later audit and A/B.
- New audit values remain in memory only. No count/hash/config column, migration, repository projection or reindex state was introduced before Plan 05.
- Phase64.3 parity must inject its candidate into the internal ingestion constructor. Merely naming `_token_candidate()` in the outer script would not prove the actual embedded bytes.
