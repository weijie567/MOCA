## Accomplishments

- Added a seven-state candidate lifecycle (`claimed`, `building`, `built`, `validating`, `complete`, `failed`, `source_stale`) that seals tenant, run, config, fresh parity, manifest, active source corpus/epoch, evidence epoch, owner, lease, and ordered document identity. Resume/checkpoint refuses foreign, expired, taken, stale, drifted, or out-of-order work through tenant locks and CAS.
- Added a corpus-qualified authoritative snapshot DTO that reads and locks only manifest-specified `PolicyDocument`, immutable document identity, and ordered `DocumentBlock` content/provenance from PostgreSQL. Each document is reloaded and hash-compared before cursor checkpoint; source files and parser entry points are never used.
- Built token DTOs through the sole `PolicyEmbeddingInputAssembler`, submitted those exact frozen strings for vectors, recounted input hash/EOS-inclusive tokens, checked provider vector cardinality/dimensions, reused canonical immutable document identity, appended compatible immutable chunk versions, and bound document/block/chunk projections only to the inactive candidate.
- Proved per-document interruption rollback leaves no candidate bindings or cursor movement, retry creates exactly one projection, candidate chunks remain absent from current active scope, and cross-tenant/run resume or rollback cannot alter another candidate.
- Sealed complete candidate proofs for exact document/block/chunk binding coverage, at-most-512 input counts, deterministic source/config rebuild, parity/source epoch identity, no mixed source, and immutable chunk replay compatibility without activating the candidate.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical functionality] Preserved immutable repository ownership without mutating shared current heads**

- **Found during:** Task 2 design and RED implementation
- **Issue:** The planned candidate must append/reuse authoritative immutable evidence, but `EvidenceVersionRepository.append_immutable_version()` unconditionally wrote the candidate sequence into shared current document/chunk heads. Bypassing the repository would duplicate compatibility and replay ownership.
- **Fix:** Added one keyword-only `project_current_head: bool = True`; ordinary callers retain exact behavior, while Plan07 candidate calls explicitly pass `False`. Real PostgreSQL regression proves ordinary projection reaches sequence 3 and candidate sequence 99 leaves both shared heads at 3.
- **Files modified:** `src/repositories/evidence_version_repo.py`, `tests/knowledge/test_document_source_identity.py`
- **Commit:** `d2e2560d`

**2. [Rule 1 - Test setup bug] Ordered source-authority fixture writes across composite foreign keys**

- **Found during:** Task 1 GREEN verification
- **Issue:** The first real PostgreSQL fixture flushed manifest/source corpus/rollout together without ORM relationships, so SQLAlchemy inserted rollout before its composite corpus target.
- **Fix:** Flushed tenant, manifest, source corpus, and rollout in explicit foreign-key order; no schema or product behavior changed.
- **Files modified:** `tests/rag/test_policy_reindex.py`, `.planning/LOCAL-VALIDATION-ISSUES.md`
- **Commit:** `1f9bfb00`
