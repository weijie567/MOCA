## Accomplishments

- Migration 030 creates tenant-scoped manifest revisions, corpus versions, one rollout pointer/epoch, append-only activation history, and explicit document/block/chunk projection bindings. Its real PostgreSQL bootstrap proves exact per-tenant before/after distinct counts, rejects orphan/duplicate/cross-tenant bindings, and refuses downgrade once token-dependent rows exist.
- Every legacy tenant with policy rows receives exactly one complete active `character.v1` corpus without rewriting immutable history. Corpus IDs remain outside document, chunk, and evidence identity.
- New ingestion derives `canonical_document_content.v2` from ordered authoritative parser blocks before assembly/chunking. The immutable snapshot retains content, provenance, source checksum, schema, and canonical hash while legacy v1 rows stay readable and SQL NULL.
- Plan04 DTO count/input-hash/config values now persist exactly on current chunks, immutable chunk versions, and ingestion jobs in the same transaction; truthful provider request totals are recorded when reported and explicitly marked unavailable otherwise.
- Same-source character/token configurations reuse one immutable document version. Compatible chunks reuse an existing chunk version; incompatible config/input/count/search/provenance appends the next chunk version, independent of corpus visibility.
