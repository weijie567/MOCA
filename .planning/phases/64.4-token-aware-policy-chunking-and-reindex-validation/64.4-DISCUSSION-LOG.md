## Tokenizer ownership and failure semantics

| Option | Description | Selected |
|--------|-------------|----------|
| Versioned model-tokenizer contract | Officially researched deterministic offline counter, provider parity evidence, fail closed on unknown/failure | ✓ |
| Heuristic tokenizer mapping | Pick a commonly used tokenizer for the model without provider authority | |
| Character fallback | Use token counts when available and silently revert to character budgets otherwise | |

**Choice:** Versioned model-tokenizer contract with explicit parity status and fail-closed production behavior.
**Notes:** Exact limit and sizing values remain research/planning decisions. Missing provider usage is recorded as unavailable, never fabricated as parity success.

## Exact final-input assembly

| Option | Description | Selected |
|--------|-------------|----------|
| Count the authoritative final input | One assembler emits citation/provenance plus the exact provider string and token count; deterministic structural splitting | ✓ |
| Count content before decoration | Size chunk content first, then append title/section/source context afterward | |
| Provider rejection/retry | Submit oversized inputs and split reactively after API errors | |

**Choice:** Count the exact immutable embedding input before submission.
**Notes:** Title, section, repeated table headers, overlap, and allowed source context consume the same hard budget. Oversized units split structurally, then by deterministic token windows; no silent truncation.

## Path convergence and compatibility

| Option | Description | Selected |
|--------|-------------|----------|
| One parsed-block assembly boundary | Production, dry-run, golden, and A/B call the same assembler; legacy character path is quarantined baseline-only | ✓ |
| Maintain two equivalent chunkers | Keep `chunk_blocks` and `chunk_markdown` separately and test for approximate parity | |
| Evaluation-only token chunker | Add token-aware logic only to Phase 64.3 A/B tooling before production migration | |

**Choice:** One production-authoritative assembly boundary.
**Notes:** Citation content, search text, and embedding input remain distinct contracts. Historical legacy material stays readable but cannot be minted by new writes.

---

## Identity-safe reindex, cutover, and rollback

| Option | Description | Selected |
|--------|-------------|----------|
| Isolated candidate plus atomic active flip | Fixed run/config identity, resumable staging, completeness gates, rollout lock/CAS cutover, prior-version rollback | ✓ |
| In-place replacement | Rewrite current chunks and embeddings incrementally in the active corpus | |
| Dual-write without atomic selection | Write old and new chunks together and filter them by best effort during retrieval | |

**Choice:** Isolated immutable candidate corpus with atomic active-version selection.
**Notes:** Queries never observe a partially mixed corpus. Configuration compatibility is explicit; incompatible rechunking creates new immutable identity while exact historical replay remains resolvable.

---

## A/B selection and completion policy

| Option | Description | Selected |
|--------|-------------|----------|
| Fixed safety and non-regression gates | Same-run character/token candidates, versioned tolerances, full quality/cost report; cut over only passing token configuration | ✓ |
| Record a red candidate as completion | Treat a failing token-aware baseline as sufficient, matching Phase 64.3's measurement policy | |
| Tune until metrics look green | Adjust thresholds or retrieval components after observing final results | |

**Choice:** Predeclared safety and same-run non-regression gates; Phase 64.4 completes only with a selected passing token-aware configuration.
**Notes:** Phase 64.3 could complete with a truthful red baseline because it was an evaluation-foundation phase. Phase 64.4's goal is replacement and safe rollout, so a red candidate remains valuable evidence but is not phase completion. Parser/retrieval target misses stay visible and owner-named rather than being silently tuned here.
