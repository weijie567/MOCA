## Critical Issues

### CR-01: A nested artifact-directory substitution can detach the reservation from the canonical budget

**Files:** `src/rag/policy_reindex_artifacts.py:148-237`, `src/rag/policy_reindex_artifacts.py:659-748`, `scripts/reindex_policies.py:598-620`

**Issue:** `_SecureReviewedArtifactIO.publish()` opens and pins the destination's nested parent at line 158, but then calls `self.exists(path)` at line 162, which independently reopens the lexical parent path. Publication uses the original `parent_fd` at lines 185-190. If an attacker or concurrent operator renames that nested directory after it is opened and replaces the canonical path with a symlink or fresh directory, the hard link is created in the now-detached original directory. The final `verify_run_chain()` and the explicit provider-before check only reopen root→`tenants/<tenant>/runs/<run>` and compare the run inode; neither verifies the nested parent or the just-published attempt through the canonical path. `reserve_candidate_build_attempt()` then returns the in-memory reservation, and `_build_next_reviewed()` constructs `EmbeddingService` even though the canonical attempt list does not contain the consumed ordinal. A failed provider attempt can therefore be repeated without reaching `max_build_executions_per_document=2`; a successful attempt can also commit DB progress before result reconciliation discovers the missing canonical reservation.

**Fix:** Make nested artifact directory identity part of the pinned namespace contract. At minimum, perform existence and create-only publication against the same parent descriptor, reopen the exact parent chain from `run_fd` after publication, compare `(st_dev, st_ino)` with the pinned parent, and strict-load the newly published reservation through that verified canonical chain immediately before provider construction. Prefer retaining and revalidating every opened artifact-directory descriptor/inode for the command, not only `run_fd`. Add a deterministic adversarial test that substitutes `build-attempts/<document_index>` between parent open and hard-link publication and proves zero provider-factory calls, canonical ordinal consumption, and no DB advance.
