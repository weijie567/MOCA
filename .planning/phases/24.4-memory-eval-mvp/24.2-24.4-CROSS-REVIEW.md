- Phase 24.2: unified Session Memory Bundle read path

## 结论

GSD code-reviewer 返回 3 个 Major findings，均按真实代码核对后判定成立并已修复。

## Findings 与处理

### 1. existing `session_memory_bundle` 缺少 scope/run identity 校验

判定：成立。

风险：checkpoint / retry / 测试注入中如果残留跨 tenant/user/thread/run 的 bundle，prompt 节点会直接消费错误记忆。

处理：

- `session_memory_bundle_from_state(...)` 增加 tenant_id / user_id / thread_id / current_run_id 校验；
- mismatched bundle 被忽略，并走 fresh load 或 fail-closed empty context；
- 补 `generate_recommendation` mismatched bundle 回归测试。

### 2. bundle load failure 回退旧 slot-continuity read path

判定：成立。

风险：prompt bundle 失败时，`state["session_memory"]` 仍可能通过旧 `MemoryService.load_session_memory(...)` 获得 trusted slots，造成 rolling/recent/tool context 与 slot continuity 不一致。

处理：

- `session_memory_load` 不再在 bundle failure 后直读 `MemoryService.load_session_memory(...)`；
- bundle 缺失时返回 empty fallback；
- bundle service 内部仍允许局部失败生成 typed empty bundle / fallback_reasons；
- 更新 graph 和 session memory load tests，让测试 fixture 走 fake bundle 而不是旧 direct MemoryService。

### 3. isolated memory write 可能早于主事务 commit

判定：成立。

风险：`finalize_completed_agent_run_memory(...)` 原先在 `_complete_run(...)` 前执行 isolated memory write；如果后续 run status / AgentStep 写入失败，memory side effect 可能已经提交。

处理：

- agent-runs SSE flow 改为先 `_complete_run(...)` 提交主 run 状态和主 trace；
- finalizer 内先提交 assistant message / rolling summary，再执行 isolated memory write；
- finalizer trace step 作为 best-effort 追加，不影响已提交的主事务和 memory side effect；
- 补强 `_complete_run` 失败测试：final_state 具备可写 slots 时，仍断言 `MemoryWriteEvent`、`SessionMemory`、finalizer step 都未写入。

## 额外本地 review 修复

发现 bundle schema 没有携带真实 `tool_name`，prompt adapter 只能从 prompt summary 首词推断。真实工具名存储在 `ToolCallRecord.tool_name`，不是 `ToolResultRecord` 字段。

处理：

- `SessionToolSummaryView` 增加可选 `tool_name`；
- conversation repository 预加载 `ToolResultRecord.tool_call`；
- bundle projector 从 `tool_call.tool_name` 投影真实工具名；
- prompt adapter 优先使用 bundle 中的真实 `tool_name`，仅缺失时 fallback 推断。
