<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| trusted graph config -> lifecycle adapter | Only trusted_context supplies tenant/user/thread/run identity for link/read calls. |
| lifecycle adapter -> thread_case_links | Thread-case link writer crosses from runtime state into durable tenant-scoped association. |
| lifecycle adapter -> AgentState | Active CWC crosses from DB to prompt/runtime state as contextual-only data. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-45-01 | S/I | `reviewed_memory_context_retrieve`, `link_and_load_active` | mitigate | Parse tenant_id/user_id/thread_id/run_id only from trusted_context; resolve case through tenant-scoped resolver; read CWC by tenant_id + case_id. |
| T-45-02 | E | `case_working_context`, `memory_context_bundle` | mitigate | Add separate `case_working_context` fields with contextual-only status; never write EvidenceRefV1, BusinessFactRefV1, approval, action, or replay fields from CWC. |
| T-45-03 | I | active CWC payload | mitigate | Project active CWC through Phase 44 typed content and refs; do not source CWC from `case_memories`, candidate slots, raw tool payloads, or policy body text. |
| T-45-04 | D | memory_context_load path | mitigate | Lifecycle failures return explicit skipped/error status and node_errors; reviewed memory continues with existing fallback behavior instead of aborting the run. |
| T-45-05 | R | thread-case lifecycle auditability | mitigate | Link status includes run_id/case_id/reason_code; link uses `link_source="run_auto"` and `linked_by_run_id=current_run_id`. |
| T-45-06 | T | active CWC conflict/overwrite | mitigate | This plan is read/link only; it performs no CWC content writes. Write conflict mitigation is implemented in 45-03 using expected_version and service conflict skip. |
</threat_model>
