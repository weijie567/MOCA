## Decisions Made

- Kept the promotion row globally scoped and limited it to independently verifiable protected-code, review/security, attestation, gate-report, request-hash, and DB-time values; no reviewer identity, caller, environment, path, or self-hash can authorize work.
- Put purpose and exact envelopes only on reservations, while the root binds tenant, run, candidate, promotion, config, parity, source/evidence epochs, expiry intersection, provider/model/dimensions, and the common envelope contract.
- Added `request_limit` to results with a composite foreign key to `(reservation_id, tenant_id, max_request_count)`, allowing a local CHECK to enforce the exact DB-reserved upper bound without application cooperation.
- Used `activation_history_id` as the lineage primary key with no unique selected-reference constraint; the reason-specific CHECK requires all selected fields for cutover/restore and all NULL for rollback.
- Left SC-64.4-5/6 open: this plan supplies schema primitives only; repository dispatch, fresh live authority, canonical A-B, and the activation drill belong to later plans.
