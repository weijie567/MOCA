## Critical Issues

### CR-01: Promotion ignores dirty changes to provider dispatch and the checker itself

**Files:** `src/repositories/provider_execution_authority_repo.py:50-55,71-88,514-546`; `scripts/check_phase64_5_gate.py:194-200,321-337,605-622`

**Issue:** `PROTECTED_CODE_PATHS` contains only the migration, ORM, authority DTO, and authority repository. The same incomplete tuple is used for attestation sealing, promotion-candidate creation, C0→C1 diff hashing, promotion validation, and every current-promotion dirty check. It excludes the files that own the production hard-disable and routing (`scripts/reindex_policies.py`, `scripts/eval_rag_token_chunk_ab.py`), provider-capable services, request-envelope construction, retry behavior, `EmbeddingService`, and `check_phase64_5_gate.py` itself. An uncommitted edit to one of those files leaves `HEAD`/`HEAD^{tree}` unchanged and is invisible to the path-limited `git status`, so the repository continues to accept the existing promotion. Such an edit can remove a hard-disable, change the sealed call graph, bypass the authority service, or alter the checker while still being reported as the reviewed C1 code identity. This defeats the explicit review/promotion authorization boundary.

**Fix:** Define one authoritative protected production graph that includes every provider constructor, dispatch helper, hard-disable, envelope owner, and the checker, and use that identical graph for dirty checks, C0→C1 diff hashing, attestation tests, and repository promotion validation. At minimum it must include the current authority files plus `src/rag/policy_reindex.py`, `scripts/reindex_policies.py`, `src/rag/evaluation/token_chunk_ab.py`, `scripts/eval_rag_token_chunk_ab.py`, `src/rag/embedder.py`, and `scripts/check_phase64_5_gate.py`, together with any transitive production modules that can change provider request enumeration or reachability. Add a parameterized negative test that dirties each protected path and proves seal, candidate, promote, issue, reserve, and recheck all refuse before provider construction.

```python
PROTECTED_CODE_PATHS = AUTHORITY_PATHS + PROVIDER_DISPATCH_PATHS + ENVELOPE_PATHS + CHECKER_PATHS

# Every gate and repository check must consume this same complete tuple.
dirty = _git_bytes(root, "status", "--porcelain=v1", "--untracked-files=all", "--", *PROTECTED_CODE_PATHS)
if dirty:
    raise PromotionStale(...)
```

## Warnings

### WR-01: Every canonical A/B unavailable/error result fails the service's own input identity check

**Files:** `scripts/eval_rag_token_chunk_ab.py:237-243,263-285,370-419,562-592,1019-1083`; `src/rag/evaluation/token_chunk_ab.py:801-814`

**Issue:** `main()` computes the canonical `ordered_questions_sha256` and passes that `inputs` object into `CanonicalABExecutionService`. All unavailable and execution-error branches in `run_full_provider_ab()`, however, call `_terminal_without_observations()`, which reconstructs `_inputs(args)` without the ordered-question hash and therefore seals all zeroes. After the reservation has committed, the service rejects the returned report at `report.inputs != inputs`. No terminal DB result or projection is recorded, and an intended `provider_unavailable` result cannot authorize the one allowlisted unchanged ordinal-two retry. The failure is treated as an ambiguous spent crash rather than truthful terminal evidence.

**Fix:** Compute `ABInputIdentityV1` exactly once before reservation and pass that object into `run_full_provider_ab()` and `_terminal_without_observations()`; do not reconstruct it with a sentinel hash. Exercise parity-unavailable, provider-unavailable, typed runtime failure, and unknown-error returns through `CanonicalABExecutionService` and assert each commits its intended result/projection with the exact reservation subject identity.

### WR-02: Selected-pass artifacts are not bound to the authority owner's exact candidate lineage

**File:** `src/rag/evaluation/token_chunk_ab.py:813-826,1279-1307,2917-2945`

**Issue:** The execution service checks only `report.inputs`, the runtime tenant, and whether a binding is present. It does not require the report's candidate/incumbent or the binding's candidate ID, candidate run token, lease owner, and source manifest hash to equal the `PolicyReindexRunIdentity` used to seal the reservation. The downstream writers only compare the binding to the report's tenant/candidate. A selected report plus binding for a different candidate can therefore create selection and activation-authorization bytes, while the DB result independently records `output_candidate_id=owner.corpus_version_id`. The hashes then claim two different lineages beneath one successful reservation.

**Fix:** Before any terminal file is written, compare the report runtime and every `ABSelectionBindingV1` field to the exact owner and reservation subject (including incumbent, candidate, parity/config, run token, lease owner, and source manifest hash). Reject on the first mismatch and add negative tests that mutate each field while asserting no terminal/selection/authorization/result/projection write occurs.

### WR-03: Typed A/B failures are discarded and non-retryable proof failures are labeled transient

**File:** `scripts/eval_rag_token_chunk_ab.py:458-521,562-576,1029-1036,1067-1072`

**Issue:** `SafeRoleExecutionError` covers role setup, ingestion, provider request, resource-proof, and rollback-proof failures, but the catch block maps every instance to `transient_execution_error`. Resource/rollback/setup failures are not evidence that a second full-provider execution is safe; once recorded, that code is sufficient for the DB to permit ordinal two. The wrapper then drops the returned `SafeRoleFailureV1` as `_failure`, while `persist_terminal()` fabricates a `candidate_pair_invalid` shared-preflight diagnostic for every execution error. Thus the immutable diagnostic is not the failure that occurred, and deterministic safety/proof failures can be misclassified as retryable.

**Fix:** Carry the typed failure through one execution-outcome object into persistence. Map only the explicitly allowlisted transient provider-request condition to `transient_execution_error`; map setup, resource, rollback, response, projection, and unknown cases to their terminal codes. Persist the exact safe typed diagnostic, then test every `SafeRoleFailureV1.reason_code` against both its DB result code and ordinal-two eligibility.

### WR-04: Promotion-candidate C0 evidence hashes are stored but never enforced

**File:** `scripts/check_phase64_5_gate.py:263-304,307-343,359-408`

**Issue:** `create_promotion_candidate()` stores both C0 attestation hashes, both standard-artifact hashes, and the C0 gate-report hash. `build_promotion_request()` checks only the candidate's C0/C1 commit/tree and diff; it never compares those five stored evidence fields to the four supplied attestations. It instead builds the promotion request from whichever currently supplied C0 files validate at the same commit. In addition, creation destructures the validated pair positionally even though validation permits either path order, and same-stage code/security attestations are not required to bind the same gate report. A candidate can therefore be created for one C0 evidence set (or with swapped code/security fields) and promoted with a different set without triggering `promotion_candidate_attestation_mismatch`, contrary to the candidate's stated C0 binding.

**Fix:** Index C0 attestations by `(stage, kind)` at creation and request construction. Require the candidate's stored attestation, artifact, and gate hashes to equal the supplied code/security evidence; require both attestations in each stage to bind the same stage gate report. Add swapped-path and same-commit/replaced-attestation adversarial tests.

### WR-05: Checker path validation mutates and follows paths before proving containment

**File:** `scripts/check_phase64_5_gate.py:637-659,737-742`

**Issue:** `_trusted_output_root()` calls `mkdir(parents=True)` before inspecting path components for symlinks. A repository-local symlink to an external directory plus a missing descendant therefore creates directories outside the repository before the helper notices the symlink and refuses. The later check/write also has a parent-swap TOCTOU window. Separately, `_candidate_from_directory()` uses this mutating output helper for a lookup path, so a supposedly read-only `promotion-status --infer-unique-candidate-from` invocation creates a missing directory before returning `promotion_candidate_not_unique`. This violates both path containment and the Plan 04 requirement that non-promotion checker modes remain read-only.

**Fix:** Use a strict, noncreating existing-directory resolver for candidate lookup. For output creation, walk existing components with `lstat`/directory descriptors, reject symlinks before creation, and create/open each descendant relative to a trusted directory descriptor with no-follow semantics so parent swaps cannot redirect writes. Add tests proving missing read paths and symlinked descendants make no filesystem change inside or outside the repository.
