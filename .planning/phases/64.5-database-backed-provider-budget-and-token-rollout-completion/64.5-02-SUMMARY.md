## Decisions Made

- Derived current protected-code identity internally from the repository checkout; request fields cannot assert their own commit/tree authority.
- Required current promotion twice across the service/repository mutation seam, then revalidated source, evidence, candidate, parity, expiry, and envelope under row/advisory locks.
- Kept one root shared by reviewed build and canonical A-B, with each child reservation owning its purpose-specific subject and exact ordered request envelope.
- Treated reservation commit as the budget event. A process crash before provider work or result persistence cannot recycle ordinal 1 and does not qualify for ordinal 2.
- Allowed ordinal 2 only after an immutable ordinal-1 `provider_unavailable` or `transient_execution_error` result and byte-for-byte matching subject/envelope; terminal quality, safety, and configuration outcomes stop.
- Kept result recording available for the already committed reservation even if execution authority later expires, so a terminal outcome is not lost; it cannot authorize another call outside the closed retry rule.
- Made reconciliation historical and one-way: it reads an exact locked DB graph and atomically creates identical bytes, but never accepts projection bytes as an input to DB state.
