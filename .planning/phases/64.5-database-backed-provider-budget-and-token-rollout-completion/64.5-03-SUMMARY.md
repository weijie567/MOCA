## CLI and Service Contracts

- Issuance: `issue-provider-authority --artifact-root ROOT --tenant-id UUID --run-token UUID --parity-report PATH`. It returns the committed `authority_id` and create-only projection metadata; there are no purpose, envelope, provider, enable, override, or alternate-root options.
- Internal reviewed build: `ReviewedPolicyCandidateBuildService.build_next_document(owner, authority_id, assembler, ordinal, projection_path)`.
- Parsed reviewed build parameters include the DB `authority_id` and ordinal 1/2, but production dispatch returns `live_provider_execution_disabled` before reading either identity, touching the DB/artifact root, reserving, or constructing a provider.
- Issuance projects to `provider-authority.v2.json`; terminal document graphs project to fixed `provider-authority.document-{index}.ordinal-{ordinal}.v2.json` paths so create-only bytes never overwrite an earlier append-only graph.

## Envelope and Commit Order

For `N` deterministic embedding inputs, the service fixes `B = ceil(N / 10)` ordered batch call sites. Each site seals its batch input count and ordered hash; `maximum_attempts_per_site` is `B` ones, `maximum_request_count = B`, provider/model/dimensions match the authority root, SDK retries are zero, and the reviewed outer attempt count is one.

The execution sequence is:

1. require the current DB promotion/current protected C1 identity;
2. prepare the exact inactive candidate document and match the current DB authority root;
3. reserve and commit the document ordinal independently;
4. re-lock and recheck promotion, candidate, source, root, and envelope with DB time;
5. construct and call the provider outside reservation/candidate transactions;
6. commit candidate progress, then immutable result, then DB-derived projection.

A `BaseException` after reservation commit records no fabricated result and leaves the ordinal spent for repository reconciliation. Ordinary terminal exceptions record the closed result code before projection and do not activate the candidate.

## Negative Coverage

- Missing, stale, dirty, foreign, or mismatched promotion/protected-tree identity closes before reservation/provider construction.
- Missing, expired, copied, conflicting, or drifted authority/source/parity/config/lease/envelope state closes before unauthorized provider work.
- A copied V2 projection plus known UUID cannot substitute for the missing DB row.
- A conflicting second shared root is rejected with `authority_mismatch`; the exact root remains idempotent and sole.
- Crash after committed reservation cannot fabricate success or refund/reuse ordinal 1.
- Phase 64.4 file budgets are never consumed by the reviewed DB path.
- Both reviewed and legacy production commands stop at the earliest hard-disable gate with zero side effects.
