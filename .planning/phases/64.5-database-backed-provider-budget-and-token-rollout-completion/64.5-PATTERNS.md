## Shared Patterns

### Database authority and transaction order

1. Tenant advisory lock (`policy_corpus_repo.py:251-255`).
2. Deterministic `FOR UPDATE` row order (`policy_corpus_repo.py:257-266`; `rag_evaluation_round_repo.py:827-863`).
3. Validate every bound identity and strict expiry using trusted DB time.
4. Insert unique reservation, flush, and commit in a short independent transaction.
5. Recheck immediately before provider construction; provider work runs outside the reservation transaction.
6. Persist create-only result/projection separately. Missing result after a crash never frees an ordinal.

### Validation and diagnostics

- Use `ConfigDict(extra="forbid", frozen=True)` (`token_chunk_ab.py:70-71`).
- Bind canonical hashes, enum/literal outcomes, positive ordinals/counts, exact configuration, and request-envelope limits.
- Raise allowlisted reason codes without raw exception/provider payload, credentials, paths, or database URLs; see `tests/eval/test_rag_token_chunk_ab.py:1780-1798`.
- Expiry equality refuses (`db_now < expiry` is required); no operator timestamp is authority.

### Testing

- Migration/concurrency claims require PostgreSQL and independent sessions; copy `NullPool` migration tests and the concurrent CAS test.
- Every provider-capable path needs a before-provider negative with counters for DB, root, artifact, reservation, and provider.
- Test both successful uniqueness and crash ambiguity: committed reservation with no result remains spent.
- Use only `UV_CACHE_DIR=/tmp/uv-cache uv run pytest ...` or verified `.venv/bin/pytest ...`; bare pytest results are invalid in MOCA.

### File projections

Files are create-only, canonical, hash-checked projections. Copying, deleting, or reconstructing a file can recover evidence only; it cannot create or extend authority. Preserve all Phase 64.4 V1 bytes/loaders unchanged.
