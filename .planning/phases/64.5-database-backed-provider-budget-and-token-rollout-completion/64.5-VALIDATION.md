> Per-phase validation contract for database authority, provider dispatch, live evaluation, and reversible rollout.

## Test Infrastructure

| Property | Value |
|---|---|
| **Framework** | pytest 9.0.3, pytest-asyncio 1.3.0, SQLAlchemy/asyncpg against real PostgreSQL |
| **Config files** | `pyproject.toml`, `tests/conftest.py`, `docker-compose.yml` |

| **Plan gate** | `make format`, full `make lint`, then the plan's exact scoped project-entry suite |
| **Final suite command** | `UV_CACHE_DIR=/tmp/uv-cache uv run pytest -q` |
| **Estimated runtime** | Focused 1–180 seconds; final suite about 40 minutes from Phase 64.4 evidence |

Bare `pytest` and bare `python -m pytest` are invalid verification in MOCA.

## Sampling Rate

- After each minimal Wave-0 test: run the exact node immediately and preserve the intended RED reason before adding more cases.
- After every Python task: run `make format`, full `make lint`, then that task's exact scoped suite.
- After each plan: rerun the plan union and `git diff --check` before SUMMARY/self-check.
- Plans 01–05: use independent PostgreSQL sessions for migration, contention, crash, replay, and before-provider assertions; SQLite/mock-only evidence is insufficient.
- Plan 05: run an interim deep code review and security audit before production dispatch is enabled; any open blocker stops the chain.
- Plans 06–08: live gates are strictly serial and never CI-parallelized.
- Before final verification/PR: full `make lint` and full project-entry pytest must pass.
