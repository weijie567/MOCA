## Spec Consistency Findings

- Implemented fact: `src/repositories/approval_repo.py::decide` mutates one request row and supports only `approve|reject`.
- Target contract: `ApprovalService` owns `accept|approve|edit|respond|reject|ignore|expire` transitions with request/level/assignment CAS and exact hash binding.
- MVP scope for this plan: implement create/request and decision transitions for single-level runtime plus schema-compatible level/assignment model. `respond` and `edit` detailed revalidation are completed in Plan 05.

## Architecture Alignment

Canonical owner package: `src/approvals`. `ApprovalService` owns executable transitions, `src/approvals/repository.py` owns target table writes, `src/approvals/policy.py` owns role/self-approval decisions, and `src/approvals/schemas.py` owns trusted commands/results.
Old-path strategy: `src.repositories.approval_repo` is not extended for target behavior and is deleted or quarantined in Plan 13-07.
Forbidden imports: API routers and graph nodes become callers in Plan 04 and must not perform direct table mutations, raw decision construction, or legacy repository transitions.
Boundary tests: Plan 13-07 static tests verify no router/graph/test imports reintroduce the legacy transition owner.
Non-overlap: Phase 13 owns approval state, hashes, and single-level runtime; Phase 14 owns action draft/executor binding; Phase 15 owns replay enrichment and scanner enablement; Phase 16 owns memory; Phase 17 owns external execution.

## Migration / Read-Switch / Rollback

Read-switch owner is `src/approvals/repository.py`. It reads/writes v2 target rows and treats v1 rows as non-executable when hashes or v2 level/assignment rows are missing. Rollback is to stop calling `ApprovalService` and downgrade schema via Plan 02 rollback before any external effects; Phase 13 has no external action dispatch.
