<planning_gate>
## Spec Consistency Findings

- Implemented fact: API routers currently import `ApprovalRepository`, check role/self/expiry inline, call `repo.decide`, build `Command(resume=...)`, and update run/trace after graph resume.
- Target contract: routers authenticate/parse only, construct trusted server-side command objects, call `ApprovalService`, and wrap only service-produced resume payloads.
- MVP scope: cut over existing approval API and interrupt creation paths. Rich UI/work queue remains out of scope.

## Architecture Alignment

Canonical owner package: `src/approvals`. Approval schemas are owned by `src/approvals/schemas.py` and durable fields by `src/db/models.py`; API schemas are adapter DTOs only.
Old-path strategy: this plan removes router/agent imports of `src.repositories.approval_repo`; Plan 13-07 deletes or quarantines the legacy repository shim and forbids new transition imports.
Forbidden imports: API routers, agent run routers, graph nodes, and tests must not import legacy approval transition helpers or raw action/business adapters for approval decisions.
Boundary tests: Plan 13-07 adds static tests proving routers/graph/tests use `ApprovalService` and do not reintroduce the old path.
Non-overlap: Phase 13 owns approval request/decision/snapshot routing only; Phase 14 owns durable action draft/executor binding and demo wording; Phase 15 owns replay enrichment and scanner enablement; Phase 16 owns memory; Phase 17 owns external execution.
API is the trusted command boundary; `ApprovalService` remains truth owner. Graph nodes keep interrupt/resume mechanics but do not decide expiry, mutate request status, or accept untrusted chat state as approval result. For auto-allowed actions, graph/risk code may call the `src/approvals` owner to persist a snapshot row before draft routing.

## Migration / Read-Switch / Rollback

Read switch is code-level: agent/agent_runs approval creation uses `ApprovalService.create_request`; approval decisions use `ApprovalService.decide`. Rollback is returning callers to v1 router/repository only if Plan 02 schema is downgraded and no v2 approvals have been authorized; otherwise legacy rows remain non-executable.

## Compatibility-Layer Disposition

| Path | Owner | Forbidden New References | Protection Test | Deletion/Gate |
|------|-------|--------------------------|-----------------|---------------|
| Router import of `src.repositories.approval_repo` | Plan 04/07 | No router or agent_runs import | Plan 07 boundary test | Removed in this plan |
| Router-built `resume_payload` dict | Plan 04 | No `Command(resume={...})` assembled in router | API tests assert service payload is used | Removed in this plan |
| Raw interrupt payload row creation | Plan 04 | No direct `ApprovalRequest` creation from `interrupt_data` | integration tests | Replaced by service request creation |

## Cross-Table Enforcement Row

This plan does not implement the decision transaction row itself, but every API decision must pass the expected request/level/assignment versions into the Plan 03 service enforcing:
`approval_decisions.approval_assignment_id -> approval_assignments.id -> approval_levels.approval_request_id -> approval_requests.id`.
