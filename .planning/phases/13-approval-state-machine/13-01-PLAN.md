## Spec Consistency Findings

- Implemented fact: MOCA currently has `src/knowledge/text_hash.py` and `canonical_evidence_projection`, but no `src/common/canonical_hash.py`, no `ActionSafetySnapshot`, and no approval hash binding.
- Target contract: `docs/contract-spec.md` requires CanonicalHashProfile v1 and `action_safety_snapshot.v1` before approval/action authorization.
- MVP scope for this plan: hash/snapshot contract only. Approval persistence, service transitions, API resume, and action draft validation are owned by later Phase 13 plans.
- Spec reconciliation: `docs/contract-spec.md` gives an authoritative proposed_action golden hash but does not yet provide an authoritative `action_safety_snapshot.v1` digest with fixed canonical JSON/hash input. This plan freezes a Phase 13 snapshot fixture and Plan 13-08 must record the missing upstream snapshot golden as a blueprint/spec follow-up.

## Architecture Alignment

Canonical owner package: `src/approvals` owns approval snapshot construction and `src/common/canonical_hash.py` owns canonical bytes. Schema contracts live in `src/approvals/schemas.py`.
Old-path strategy: existing `policy_snapshot_ref` and `evidence_snapshot_ref` aliases remain compatibility metadata only and cannot become authorization guards.
Forbidden imports: routers, graph nodes, action services, and replay code may consume these helpers but must not define alternate serializers or hash profiles.
Boundary tests: later Phase 13 service/API/boundary tests prove downstream code uses these owners rather than local serializers.
Non-overlap: Phase 13 owns approval/snapshot binding; Phase 14 owns action draft/executor binding; Phase 15 owns replay enrichment; Phase 16 owns memory; Phase 17 owns external execution.

## Migration / Read-Switch / Rollback

No database migration is introduced in this plan. Rollback is deleting the new common/approvals modules and tests before downstream plans depend on them. The fields produced here are consumed by Plan 02 migration and Plan 03 service tests.
