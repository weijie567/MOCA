## Spec Consistency Findings

- Implemented fact: `src/agent/events.py` has base minimal event types and redaction guard, but no approval event additions.
- Target contract: Phase 13 registers approval event additions; Phase 15 later enriches full ReplayEventV3 and may enable scanner.
- MVP scope: minimal event additions and disabled scanner only. No full replay API, lifecycle finalizer, or active scheduler is implemented here.

## Architecture Alignment

Canonical owner package: `src/approvals`. `ApprovalService` owns business transition event emission; `src/approvals/events.py` is a helper around the existing minimal envelope, not a new replay system. The schema owner is the Plan 02 `approval_events` table plus the minimal event envelope in `src/agent/events.py`.
Old-path strategy: `ApprovalStep` remains trace fallback only and cannot receive new target approval event behavior; Plan 13-07 protects that with boundary/legacy tests.
Forbidden imports: event helpers and scanners must not import legacy transition repositories, raw action adapters, or business tools to fabricate decisions.
Boundary tests: Plan 13-07 forbids direct transition imports, while this plan's event tests prove minimal redacted refs are emitted from service-owned decisions.
Non-overlap: Phase 13 adds minimal event rows and a disabled scanner only; Phase 15 owns replay enrichment and scanner enablement; Phase 14 owns action draft/executor binding; Phase 16 owns memory; Phase 17 owns external execution.

## Migration / Read-Switch / Rollback

The `approval_events` table from Plan 02 stores approval audit truth with nullable `replay_event_id`. Rollback disables event helper calls and scanner config; target rows remain auditable until migration downgrade.

## Compatibility-Layer Disposition

| Path | Owner | Forbidden New References | Protection Test | Deletion/Gate |
|------|-------|--------------------------|-----------------|---------------|
| `ApprovalStep` timeline row | Trace compatibility | No new target event behavior | Plan 07 legacy tests | Remains fallback until Phase 15 |
| `agent_trace_events` minimal envelope | Phase 10 base, Phase 13 additions | No raw approval payloads | `tests/approvals/test_events.py` | Enriched by Phase 15 |
| SLA scanner active scheduling | Phase 15 enablement | Scanner must default disabled | `tests/approvals/test_sla_scanner.py` | Phase 15 replay gate |

## Cross-Table Enforcement Row

Approval events emitted from decision handling must include resource refs for request, level, assignment, decision, revision, request_version, level_version, assignment_version, `action_payload_hash`, and `safety_snapshot_hash` so Phase 15 does not fabricate decision semantics.
