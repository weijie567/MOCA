## Architecture Alignment

Owner and contract first:
- Canonical owner package: `src/actions` owns action draft contracts; `src/db/models.py` and Alembic own durable schema.
- Contract: `action_draft.v2` rows created after Phase 14 carry `schema_version="action_draft.v2"`, `action_payload_hash`, `safety_snapshot_ref`, `safety_snapshot_hash`, `target_id`, `approval_revision_ref`, `execution_mode="demo"`, `draft_version`, `lifecycle_status`, `retention_policy`, and `draft_outcome`.
- `draft_outcome.v1` shape is exactly `{"schema_version":"draft_outcome.v1","status":"not_executed_demo","external_side_effect":false,...}` with tenant/run/draft refs where available.

Move/rewrite to owner:
- Add schema helpers before service behavior uses them.
- Mirror every ORM column in the Alembic migration and contract tests.

Delete/quarantine old paths:
- Do not create `action_executions`, outbox, reconciliation, compensation, or external action tables.
- Keep legacy pre-v2 rows nullable only for migration compatibility; they are not an authorization surface.

Boundary tests before expansion:
- `tests/actions/test_action_draft_v2.py` must fail if action_drafts lacks binding/outcome columns or if migration 009 creates external-only tables.
</architecture_alignment>
