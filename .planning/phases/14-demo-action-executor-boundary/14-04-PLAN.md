## Architecture Alignment

Owner and contract first:
- Canonical owner package: API/final consumers own wording and reconciliation only; `src/agent/nodes/action_draft.py` and `src/actions` own draft creation truth.
- Contract: `draft_outcome.v1` is the only demo success signal for API/final surfaces; demo mode never claims external execution.

Move/rewrite to owner:
- Approval resume calls the canonical `action_draft` node and checks `draft_outcome.status == "not_executed_demo"` plus `external_side_effect is False`.
- Final response templates consume `draft_outcome`, not `action_result.status == "success"`.

Delete/quarantine old paths:
- Remove backend API/final success-sentinel dependency on `action_result.status == "success"` for demo draft success.
- Keep `action_result` only as the deprecated compatibility field owned by the action-draft boundary in Plans 14-02 and 14-03; this plan must not add new dependencies on it.
- Do not create `/replay`, ReplayEventV3 read switch, lifecycle finalizer, retention model, action execution, outbox, reconciliation, compensation, or external adapter calls.

Boundary tests before expansion:
- Add forbidden phrase tests before changing final/API wording.
- Add regression assertions for missing or externally side-effecting `draft_outcome` so invalid state cannot be treated as success.
</architecture_alignment>
