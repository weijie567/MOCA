<architecture_alignment>
## Architecture Alignment

Owner and contract first:
- Canonical owner package: `src/actions` owns idempotency, exact binding reuse, and draft outcome creation.
- Contract: key shape is exactly `{tenant_id}:{run_id}:{approval_revision_or_auto}:{action_type}:{target_id}:{action_payload_hash}`. The no-approval marker is exactly `auto_allowed`.

Move/rewrite to owner:
- Move idempotency construction out of graph/tool callers and into `ActionService`.
- Repository only receives a service-built key plus binding fields and enforces exact reuse.
- Define `AgentState.action_draft`, `AgentState.draft_outcome`, and `AgentState.execution_mode` before the graph node writes those keys, and reset them in `receive_request` so checkpointed stale values cannot satisfy later API/final consumers.

Delete/quarantine old paths:
- Stop accepting caller-provided arbitrary draft idempotency key shapes for `create_coupon_grant_draft`.
- Keep `ActionSafetySnapshot` validation in Phase 13-owned `_validate_action_binding`; do not recompute or mutate snapshots.
- Retain `action_result` only as Phase 14 action-draft-boundary-owned deprecated compatibility output while graph/API/final consumers move to `draft_outcome`. It must never use `status="success"` to claim external execution. Replacement/removal gate: Phase 15 Replay Event Contract before Phase 15 verification, target no later than 2026-07-16 unless Phase 15 is replanned.

Boundary tests before expansion:
- Service tests must fail on missing `target_id`, mismatched snapshot hash on key reuse, and caller-supplied unsafe key shapes.
</architecture_alignment>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Graph/tool caller -> ActionService | Caller input is untrusted for idempotency key shape and target validation. |
| ActionService -> ActionDraftRepository | Service-built key and Phase 13 binding fields become durable authorization facts. |
| Existing draft row -> idempotent reuse | Reuse must prove exact binding, not just matching key text. |
| Checkpointed state -> new turn | Stale draft outcome fields must not leak from a prior graph turn into API/final consumers. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T14-01 | Elevation of Privilege | `ActionService` | mitigate | Service persists only draft rows and returns `external_side_effect=false`; no adapter/outbox/execution code is introduced. |
| T14-02 | Tampering | `ActionDraftRepository.create_or_get` | mitigate | Existing-key reuse checks tenant, run, action type, target id, payload hash, snapshot ref, and snapshot hash; mismatch raises idempotency conflict. |
| T14-03 | Tampering | `ActionService.create_coupon_grant_draft` | mitigate | Missing or blank target id returns `TARGET_ID_REQUIRED`; no `"unknown"` fallback remains. |
| T14-04 | Spoofing / Repudiation | service/tool result | mitigate | Canonical success is `draft_outcome.status="not_executed_demo"` with `external_side_effect=false`; Plan 04 adds final/API wording tests. |
| T14-05 | Information Disclosure | service/tool result | mitigate | Result exposes draft refs/hashes/outcome only; raw payload trace/event redaction is handled in Plan 04. |
| T14-06 | Elevation of Privilege | compatibility path | mitigate | This plan does not add an `execute_action` alias; Plan 03 quarantines any retained shim and forbids new imports. |
| T14-07 | Tampering | `receive_request` state reset | mitigate | `action_draft`, `draft_outcome`, and `execution_mode` are defined in `AgentState` and reset to `None` before each turn. |
</threat_model>
