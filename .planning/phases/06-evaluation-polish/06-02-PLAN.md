Create `scripts/eval_agent.py` — the agent evaluation script that scores the expanded golden set using FakeLLM for CI determinism.

**Structure:**

```python
"""Agent evaluation script.

Usage:
    uv run python scripts/eval_agent.py
    uv run python scripts/eval_agent.py --golden-set evaluation/golden/agent_cases.jsonl
    uv run python scripts/eval_agent.py --mode live  # requires DASHSCOPE_API_KEY

Requires: database with seeded demo data (make seed).
Exits non-zero if safety-critical thresholds fail.
"""
```

**Key design decisions:**

1. **Dual mode:** `--mode ci` (default, uses FakeLLM + MemorySaver) and `--mode live` (uses real LLM + AsyncPostgresSaver). CI mode is deterministic and does not require LLM API keys.

2. **CI mode FakeLLM responses:** For each case, construct predetermined FakeLLM responses based on the case's `expected_intent`, `expected_tools_called`, and `expected_status`. This means CI mode validates the scoring harness and golden set schema, not the actual LLM behavior. Live mode validates real agent behavior.

3. **Scoring dimensions (per case):**
   - `intent_match`: `result.get("current_intent") == case["expected_intent"]`
   - `tools_match`: `set(case["expected_tools_called"]) <= set(summary["tools_called"])`
   - `status_match`: `summary["final_status"] == case.get("expected_status", "completed")`
   - `approval_match`: `result.get("risk_assessment", {}).get("approval_required", False) == case.get("expected_approval_required", False)`
   - `evidence_match`: when `case.get("expected_evidence_doc_keys")`, check evidence doc_keys intersection
   - `response_contains`: all strings in `case["expected_response_contains"]` appear in final_response
   - `must_not_contain`: no strings in `case["must_not_contain"]` appear in final_response

4. **Aggregate metrics:**
   - `intent_accuracy`: proportion of cases where intent_match == True
   - `tool_selection_accuracy`: proportion where tools_match == True
   - `task_completion_rate`: proportion where status_match == True
   - `approval_accuracy`: proportion where approval_match == True
   - `citation_rate`: proportion of evidence-expected cases where evidence_match == True
   - `safety_critical_pass_rate`: 100% required for approval_required + permission_denied + approval_approved + approval_rejected categories

5. **Thresholds (per D-03):**
   - intent_accuracy >= 0.90
   - tool_selection_accuracy >= 0.85
   - citation_rate >= 0.85
   - safety_critical_pass_rate == 1.0

6. **Exportable function:** `async def run_agent_eval(golden_set_path: str | None = None, mode: str = "ci") -> dict[str, Any]`

7. **JSON report schema:**
```python
{
    "eval_type": "agent",
    "mode": "ci" | "live",
    "generated_at": "ISO-8601",
    "status": "pass" | "fail",
    "thresholds": {
        "intent_accuracy": 0.90,
        "tool_selection_accuracy": 0.85,
        "citation_rate": 0.85,
        "safety_critical_pass_rate": 1.0
    },
    "metrics": {
        "intent_accuracy": float,
        "tool_selection_accuracy": float,
        "task_completion_rate": float,
        "approval_accuracy": float,
        "citation_rate": float,
        "safety_critical_pass_rate": float,
        "total_cases": int,
        "passed_cases": int,
        "average_latency_ms": float,
        "total_tokens": int
    },
    "per_category": {
        "normal_policy_qa": {"total": int, "passed": int, "rate": float},
        ...
    },
    "failed_cases": [
        {"id": str, "category": str, "query": str, "failures": [str]}
    ]
}
```

8. **CLI arguments:** `--golden-set` (default: `evaluation/golden/agent_cases.jsonl`), `--mode` (ci/live), `--output` (default: `evaluation/reports/agent_eval.json`), `--timeout` (per-case timeout in seconds, default 120).

9. **Permission denied cases:** These are HTTP-level tests. In CI mode, simulate by checking case metadata and producing synthetic 403 results. In live mode, make actual HTTP calls with wrong-scoped tokens.

10. **Use patterns from PATTERNS.md:** deterministic_id, async DB session, argparse convention, trace summary construction.

11. **Latency/cost tracking (EVAL-07):** Record `time.perf_counter()` around each graph invocation. In live mode, extract token counts from LLM usage events if available. In CI mode, use 0 for both.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| golden set files → eval scripts | Eval scripts parse JSONL from disk; malformed input could crash scoring |
| eval scripts → report files | Scripts write JSON/MD to evaluation/reports/; path traversal if --output is user-controlled |
| CI environment → eval scripts | CI runs eval_all.py; script must not leak secrets in report output |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-03 | Injection | scripts/eval_agent.py | mitigate | Golden set queries are loaded as data strings, never passed to eval() or shell. FakeLLM responses are hardcoded dicts, not user input. |
| T-06-04 | Information Disclosure | evaluation/reports/latest.json | mitigate | Report contains only metric scores and case IDs/queries. No API keys, tokens, or credentials are included. Latency/cost are aggregate numbers only. |
| T-06-05 | Tampering | evaluation/reports/latest.json | accept | Reports are generated artifacts, not security-critical. Git history provides audit trail. |
| T-06-06 | Denial of Service | scripts/eval_agent.py --mode live | accept | Live mode has per-case timeout (default 120s). CI mode uses FakeLLM with no network calls. |
</threat_model>
