## Warnings

### WR-01: Default Agent Eval Does Not Exercise The Graph

**File:** `scripts/eval_agent.py:192`
**Issue:** CI mode builds a synthetic state and trace from the expected fields in each golden case, then scores that synthetic state. `_ci_fake_llm_responses(case)` is called but its return value is discarded, `build_graph(...)` is never invoked in CI mode, and `_assert_ci_routing()` checks nodes generated by `_expected_nodes_for_case()` rather than nodes produced by the actual graph. This means `make eval-agent` and the agent half of `make eval` can pass even if graph routing, node names, approval interrupts, tool wiring, or final status derivation regress.
**Fix:** Run the compiled graph in CI mode with patched deterministic LLM/tool dependencies, similar to the existing graph tests, and score the actual final state. Keep the synthetic builder only as a unit test fixture for the scorer.

```python
async def _run_case_ci(case: dict[str, Any]) -> dict[str, Any]:
    from langgraph.checkpoint.memory import MemorySaver
    from src.agent.graph import build_graph

    fake_llms = _ci_fake_llm_responses(case)
    with patch_ci_dependencies(fake_llms, case):
        graph = build_graph(MemorySaver())
        result = await graph.ainvoke(_ci_input_state(case), _ci_config(case))

    summary = build_trace_summary(result["current_run_id"], result, 0)
    assertions = _assert_ci_routing(case, summary)
    scores = _score_case(case, result, summary, latency_ms=None, total_tokens=0, routing_failures=assertions)
    return {"case": case, "result": result, "trace_summary": summary, "scores": scores}
```

### WR-02: Demo Script Continues After Failed Core Chat Flow

**File:** `scripts/demo_phase6.sh:105`
**Issue:** Preflight treats HTTP 500 from `/api/v1/agent/chat` as acceptable, and `post_chat()` only checks the curl exit code plus JSON parsing, not `.success` or required fields. If the agent path is misconfigured or returns `success:false`, the script can continue, use an empty `approval_id`, run the permission scenario against a placeholder UUID, skip manager rejection, and still print `Demo complete.` That can produce a false-positive interview demo while the approval flow never worked.
**Fix:** Fail preflight unless chat returns a successful response or a deliberately expected validation status, and make each scenario assert the fields it needs before continuing.

```bash
http_code=$(curl -s -o /tmp/moca-preflight-chat.json -w "%{http_code}" -X POST "$BASE_URL/api/v1/agent/chat" \
  -H "Authorization: Bearer $AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"query":"平台的退款超时处理规则是什么？","thread_id":"preflight"}')
if [[ "$http_code" != "200" ]] || ! jq -e '.success == true' /tmp/moca-preflight-chat.json >/dev/null; then
  echo "FAIL: Agent chat endpoint returned HTTP $http_code or success=false"
  exit 1
fi
```

For scenario 4, also require `approval_id` before scenario 5:

```bash
APPROVAL_ID=$(echo "$CHAT_RESPONSE" | jq -er '.data.approval_id')
```
