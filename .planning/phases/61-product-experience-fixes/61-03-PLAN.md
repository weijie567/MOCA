<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Token scopes -> tool permission | Only verified token scopes intersected with role scopes can grant `tool:query_business_metric`. |
| Tool args -> BusinessFactService query | Tool input is validated and scope-filtered before any SQLAlchemy query runs. |
| Database rows -> tool result projection | Raw rows/errors must be projected into typed metric results and safe summaries. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-61-03-01 | Elevation of privilege | `TrustedContextFactory` metric permission | mitigate | Add tests for role/token intersection and no user/LLM permission override. |
| T-61-03-02 | Information disclosure | metric service scope denial | mitigate | No-leak denial result with no metric data/fact refs/merchant identifiers. |
| T-61-03-03 | Tampering | metric SQL construction | mitigate | Use SQLAlchemy expressions and schema-validated enum inputs, no dynamic SQL strings. |
| T-61-03-04 | Repudiation | metric tool provenance | mitigate | Emit `BusinessFactRefV1(resource_type="business_metric")` and tool policy events. |
</threat_model>
