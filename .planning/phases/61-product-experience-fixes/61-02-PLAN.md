<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User/LLM classification -> intent policy | LLM can propose intent/slots but policy owns admitted intent and required slots. |
| Candidate metric slots -> active slots | Candidate slots must not become active slots unless slot-resolution validates them. |
| User merchant text -> trusted scope | User text can request a merchant filter but cannot widen scope. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-61-02-01 | Tampering | `IntentLiteral`/policy registry | mitigate | Registry and golden tests reject per-metric intents and unknown metric IDs. |
| T-61-02-02 | Elevation of privilege | metric merchant filter | mitigate | Scope is validated later from trusted context; this plan prevents user text from being treated as authority. |
| T-61-02-03 | Information disclosure | metric clarification | mitigate | No-existence-leak wording and tests for unauthorized merchant prompts. |
</threat_model>
