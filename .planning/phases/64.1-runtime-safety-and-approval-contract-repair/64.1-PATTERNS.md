## 3. Trusted Narrow Capability: Mint -> Verify -> Consume

### Recommended ownership split from current patterns

1. **Mint:** trusted backend service receives trusted tenant/actor/run plus canonical action, immutable hashes, deterministic allow decision and merchant scope; returns signed/opaque short-lived capability.
2. **Verify:** capability service verifies signature/key id, expiry, nonce/use state, actor/run/tenant/merchant/action/hash/handler equality; failures use stable non-secret error codes.
3. **Consume:** only the single durable demo draft handler may atomically consume/redeem; replay either returns the same idempotent draft for the exact binding or closes without a new row.

| Likely file | Role | Closest existing pattern |
|---|---|---|
| `src/approvals/schemas.py` | 扩展/替换 `AutoAllowedActionBindingV1` 的 payload contract | 当前 binding 已含 tenant/run/merchant、payload/snapshot hashes、risk/evidence refs、idempotency（63-80），但缺 actor/canonical action/handler/issued/expiry/nonce/key/signature |
| likely new `src/actions/capabilities.py` (or domain-equivalent service module) | server mint + verify API；集中 crypto/key/version/expiry semantics | 仓库暂无满足 D-10 的现成 capability owner；不要继续让 graph node 自构造可信 binding。模型可复用 strict Pydantic/canonical hash 风格，而非客户端 permission |
| `src/agent/nodes/risk_gate.py` | deterministic allow 后请求 trusted mint，node 只携带 opaque/bounded result | 当前 node 直接构造 `AutoAllowedActionBindingV1`（734-763、859-899），正是需要移出 node trust boundary 的位置 |
| `src/agent/nodes/action_draft.py` | 在调用唯一 tool handler 前验证 trusted capability；approval-resume 使用不同 authorization source | 当前 `_trusted_auto_allowed_binding` 做 tenant/run/hash/binding equality（286-325），`action_draft` 区分 approved 与 auto binding（444-493），并通过 `caller_node="action_draft"` 和固定 action tool 构造 tool context（529-564） |

## 6. Plan Slicing Suggested By Dependencies

仓库文件面确认该 phase 必须拆分，不能成为一个大 plan：

1. **Canonical action + routing**：taxonomy/state/recommendation/routing + focused guards/tests。
2. **Deterministic risk registry**：risk rules/evaluator/snapshot parity + fallback matrix。
3. **Approval context parity**：domain DTO/service -> API list/get/SSE -> frontend validator/serializer/UI state。
4. **Bounded capability + draft invariant**：server mint/verify/consume、action node/service、replay/cross-scope tests。
5. **Failure terminal propagation**：action-draft router、final suppression、run/SSE/reconcile persistence。
6. **End-to-end matrix + architecture guards**：中英文/unknown/LLM failure/stale/hash/cross-scope/replay/draft failure，以及 backend/frontend build/full focused suite。

其中 01 与 02 可在共享 taxonomy contract 定稿后并行；03 与 04 分别依赖 stable risk/action bindings；05 依赖 04 的明确 failure contract；06 最后收口。所有 backend verify 使用 `UV_CACHE_DIR=/tmp/uv-cache uv run pytest ...`，frontend 使用仓库现有 Vitest/build 入口。

## 7. Confirmed Absences / Planner Warnings

- 当前仓库中没有找到满足 D-10 的 server-minted、短 TTL、actor/action/handler/nonce/key/signature bound capability service；这是新增窄 domain boundary，不应把现有 `AutoAllowedActionBindingV1` 换个名字就宣称完成。
- 当前 frontend 没有独立 ApprovalTab test；如 UI plan 涉及 dialog、stale、network ambiguity、a11y，需新增 focused component test。
- current SSE payload 比 list/get response 更完整；统一 contract 时应抽 service/domain projector，禁止以复制 SSE dict 到另两个 router 的方式修复。
- capability/replay 与 Phase 64.2 的 immutable replay identity 必须保持边界：本 phase 只做 capability 的一次性/幂等消费安全，不扩展 evidence/replay/memory identity。
