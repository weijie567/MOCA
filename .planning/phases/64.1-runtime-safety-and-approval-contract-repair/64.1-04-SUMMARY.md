- Added `auto_action_capabilities` with hashed opaque refs, unique nonces, five-minute TTL, lifecycle checks, exact trusted identity/scope/action/payload/snapshot/risk/handler bindings, and Alembic downgrade/re-upgrade coverage.
- Made `ActionService` lock and verify the row, create or recover the exact draft, transition capability state, and emit `action_draft_created` inside the same caller-owned transaction/savepoint; injected failures roll everything back.

- Kept approval and auto-capability authorization sources distinct in audit while sharing action-draft payload, snapshot, merchant, and idempotency invariants.

## Decisions Made

- Merchant authorization is bound twice: policy checks the current trusted scope against `target_merchant_id`, while the durable record stores and consume-time verifies the canonical scope hash plus exact target. This prevents both out-of-scope dispatch and context substitution.
- A capability-shaped request does not become a general ToolPlatform permission. Only the fixed node-only action handler can reach service verification, with `matched_scope=None` and `auto_action_capability.pending_verification` audit identity.
- Exact retries may return only the already-bound draft and idempotency identity; all replay or cross-binding variants create zero new drafts.
