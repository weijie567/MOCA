## Decisions Made

- The same JSON fixture is imported directly by Python and TypeScript; no generated language-specific fixture is allowed to become a second decision-context truth.
- Frontend failure/recovery tests must prove no field inference and no POST replay after stale or ambiguous outcomes; they do not emulate or announce production execution.
- Architecture scans use concrete owners, AST structure, and narrow module prefixes. Generic strings such as all of `src.business` are too broad to distinguish raw persistence access from valid Phase 62 query contracts.
- `terminal_error` is graph control vocabulary rather than a node. The architecture baseline models that distinction while requiring `action_draft` to route conditionally.
- Evidence/claim verification non-allow remains authoritative. Action-draft terminal validation runs afterward so stale action-shaped state cannot overwrite the real failure category.
