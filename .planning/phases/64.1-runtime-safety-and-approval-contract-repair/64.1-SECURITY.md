# Phase 64.1 — Security

> 本文档只核验 Phase 64.1 PLAN 已登记的威胁与 mitigation，不是无边界的新威胁扫描。

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| Recommendation -> safety route | 非受信建议必须先规范化，才能形成 material claim | action alias, schema validity, match provenance |
| Risk evaluator -> approval/capability | 确定性风险权威不得被 LLM/config 失败降级 | severity, decision, snapshot hash |
| Backend decision context -> Console -> decide | 用户显示/复核的 exact context 必须与提交前权威 GET 一致 | versions, revision, action/payload/snapshot hashes |
| Capability -> fixed draft handler | 只允许 server-minted、有时限、单次/幂等、全 binding 的 demo capability | tenant/actor/run/action/payload/risk/merchant/handler |
| Draft outcome -> terminal/API/SSE/memory | 只有耐久 draft/outcome/audit 合同完整才能成功，失败不得被洗白 | terminal status, safe message/code, memory eligibility |
| Approval decision -> resume graph | 并发恢复通过持久 attempt identity/lease 实现 single-flight | decision identity, attempt id/status/lease |
