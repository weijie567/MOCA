## Planning Blocker Before Plan 01 Can Close

The three Markdown SHA-256 values in `evaluation/rag_sources/format_parity_manifest.jsonl` are stale while the six generated PDF hashes match their files. Because the Markdown files are declared source of truth, the implementation must not merely refresh those three manifest strings. Plan 01 must first decide which Markdown revision is canonical, then either restore it or regenerate/review both PDF variants and update the complete fixture set atomically.

This is a **fixture-lineage/manual decision**, not a blocker to writing the five plans. It is a fail-closed acceptance gate for Plan 01 and all later evaluator runs.

## Recommended Concrete File Layout

Use a small project-owned package for reusable contracts/scoring/runtime and keep the executable adapter in `scripts/`, matching existing evaluator conventions:

```text
src/rag/evaluation/
  __init__.py
  contracts.py
  parser_parity.py
  retrieval_rounds.py
  reporting.py
src/repositories/rag_evaluation_round_repo.py
scripts/eval_rag_format_parity.py
```

`scripts/eval_rag_format_parity.py` should expose explicit parser/provider/full modes, but import provider/database wiring lazily. Importing and running parser mode must not construct a tenant, SQLAlchemy session, embedder, ingestion service, or retriever.

The fail-closed ownership/run-token proof should be durable. The current `PolicyDocument`, `DocumentBlock`, `PolicyChunk`, and `RagIngestionJob` rows do not jointly store an evaluation ownership marker plus expected run/round token. The closest repository pattern therefore points to a new `RagEvaluationRound` model/table and repository, rather than an in-memory CLI flag or raw SQL cleanup.

```python
def _sha256(path: Path) -> str:
    digest = hashlib.sha256()
    with path.open("rb") as stream:
        for block in iter(lambda: stream.read(1024 * 1024), b""):
            digest.update(block)
    return digest.hexdigest()
```

**Manifest record and stable serialization pattern** (lines 396-422, 431-439):

        "format": fmt,
        "path": str(path.relative_to(ROOT)),
        "source_type": source_type,
        "sha256": _sha256(path),
        "pages": _pdf_pages(path) if path.suffix == ".pdf" else None,
        "extractable_text_chars": ...,

MANIFEST_PATH.write_text(
    "".join(json.dumps(record, ensure_ascii=False, sort_keys=True) + "\n" for record in records),
    encoding="utf-8",
)

## Shared Patterns

### Tenant scope and failure semantics

**Sources:** `src/repositories/policy_document_repo.py` lines 15-34; `src/knowledge/service.py` lines 157-200.

Every persistence query must carry the explicit evaluation tenant plus exact document identity. Scope/ownership failures should deny without revealing whether another tenant has matching data. Do not reuse the first-active-tenant behavior in `scripts/eval_rag.py`.

### Lock order and immutable history

**Sources:** `src/repositories/evidence_version_repo.py` lines 1-13, 90-113; `src/rag/ingestion.py` lines 260-389.

Preserve the production lock order: rollout/owner state, document heads in deterministic order, current chunk heads, then mutation. Cleanup may remove exact current blocks/chunks/jobs after proof; it must not delete policy document heads or immutable versions.

### Safe diagnostics

**Sources:** `src/rag/ingestion.py` lines 46-126, 658-698; `src/repositories/rag_ingestion_job_repo.py` lines 91-129.

Use allowlisted mappings and stable reason codes. Exclude paths, bytes, raw payloads, parser dumps, provider contents, exceptions, tracebacks, cross-tenant state, prompts, and arbitrary nested keys.

### Stable ordering and clocks

**Sources:** `scripts/eval_rag_ablation.py` lines 93-129, 153-162; `src/knowledge/retrieval.py` lines 227-235, 701-710.

Sort at every boundary and inject timestamps for tests. Never rely on database return order, mapping insertion order from providers, or wall-clock values when comparing artifacts.

### Test doubles versus baseline truth

**Sources:** `scripts/eval_rag_ablation.py` lines 132-162; `tests/test_rag_ablation_eval.py` lines 63-83.

Deterministic fakes may validate scoring, state transitions, isolation denial, and report rendering. They must be labeled non-baseline and must fail closed if asked to claim provider-backed execution.
