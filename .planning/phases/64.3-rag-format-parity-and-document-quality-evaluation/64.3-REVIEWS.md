### Summary

The five-plan DAG `01 -> {02,03} -> 04 -> 05` is coherent and the load-bearing repository facts were confirmed: the three Markdown manifest hashes are stale while all six PDF hashes match; `IngestionService.ingest_document` commits internally; the production parser/service call shapes match the plans; migration 028 is current; current child-delete seams exist; `PolicyDocument` has no delete seam; immutable versions retain restrictive bindings; and the legacy RAG Gold hash matches.

### Strengths

- Strict 3-policy/9-variant contract, semantic Gold without chunk IDs, independent input hashes, and hash-only reconciliation prohibition.
- Direct parser evaluation mirrors production parsing while remaining persistence/retrieval independent.
- Durable evaluation ownership, exact tenant/document child cleanup, and preservation of Phase 64.2 immutable history.
- Canonical JSON owns metrics/outcomes; Markdown is a deterministic projection; fake and unavailable executions cannot write canonical baseline paths.
- Final diff/static guards protect production parser/chunker/embedder/retrieval/context/claim-verifier behavior.

### Blockers Raised

1. **Plan 01 — generator determinism:** `build_fixtures.py` must prove two runs under the recorded tool/font environment produce byte-identical PDFs and manifest; otherwise byte hashes are not a reproducible identity.
2. **Plan 01 — visual review executability:** the auto task says to visually review six PDFs but has no explicit automated/agent-verifiable evidence contract or human checkpoint.
3. **Plan 03 — internal-commit recovery:** the review claimed a crash could leave a partial block/chunk projection and asked for cleanup plus same-token re-ingestion rather than blind CAS advancement.
4. **Environment — provider closeout:** Phase 64.3 cannot close without real PostgreSQL/pgvector, embedding credentials, rollout version, and Tesseract `chi_sim+eng`; unavailable is correctly designed to block closeout.

### Warnings Raised

1. Enforce one non-terminal round per tenant with a PostgreSQL partial unique index, not application locking alone.
2. Machine-check that `baseline.json` exists and has a completed real-provider outcome before Plan 05 can turn closeout green.
3. Assert the fixed evaluation tenant is carried by `KnowledgeContext`, and capture fallback/rewrite/rerank diagnostics from an evaluation recording adapter around the real retrieval engine rather than bypassing the service.
4. Test that available-but-poor OCR (including zero anchor recall) is `completed_quality_fail`, not `unavailable_prerequisite`.
5. Define provider reproducibility as recorded input/config/toolchain identity, not bit-identical live metric results.
