## Warnings

### WR-01: Retrieval locator coverage is inferred from document rank without locator evidence

**File:** `src/rag/evaluation/retrieval_rounds.py:472-496`

**Issue:** `_case_observation()` sets `locator_covered` whenever the expected document appears in the top five. It never inspects `PolicyRetrievalRun.evidence_refs`, and the recorded hit DTO contains no page or source locator. A counterexample with the expected document at rank 1, both semantic anchors present, and an empty `evidence_refs` list reports `locator_covered=true`. This can turn missing provenance into a passing case and inflate the report's locator coverage. It also contradicts Plan 03's requirement to capture real locator observations rather than treating retrieval success as locator proof.

**Fix:** Carry a safe locator observation through the production service/recording boundary, and evaluate it against the case constraint. If the current service contract cannot supply such proof, fail the provenance observation (or classify the evaluator run as an execution error) instead of deriving it from rank. Add a regression in which the policy and anchors are retrieved but the evidence locator is absent.

```python
locator_covered = (
    case.locator_constraints is None
    or _recorded_locator_satisfies(
        recorded,
        doc_key=policy_id,
        allowed_pdf_pages=case.locator_constraints.pdf_pages,
    )
)
```

### WR-02: Parser case scoring ignores the Gold PDF page constraint

**File:** `src/rag/evaluation/parser_parity.py:373-383, 501-535, 605-610`

**Issue:** The Gold case `refund-case-time-limits` requires PDF pages 1 or 2, and `_expected_locator_summary()` publishes that constraint. Actual scoring only checks for a positive `page_number` plus a box, then reuses that anchor-level result for every case. A constructed result with both required anchors moved to page 5 still returns `case_status=passed` and `provenance_locators=passed`. The report can therefore claim provenance parity while pointing outside the accepted location.

**Fix:** Build case-specific locator matches. For PDF cases with `locator_constraints`, require each evidence anchor's matching block to have both a box and a page in `pdf_pages`; keep the current source-block check for Markdown. Use the same case-specific result for observations and `ParserCaseResultV1`, and add a wrong-page regression.

```python
allowed_pages = set(case.locator_constraints.pdf_pages) if case.locator_constraints else None
locator_ok = any(
    _has_required_locator(block, variant=variant)
    and (allowed_pages is None or block.page_number in allowed_pages)
    for block in anchor_matches[anchor_id]
)
```

### WR-03: The strict canonical loader accepts semantically contradictory reports

**File:** `src/rag/evaluation/reporting.py:77-96, 267-280, 391-402`

**Issue:** `load_format_parity_report()` performs schema and unsafe-value validation, but the model does not enforce the immutable target profile or the semantic relationship among metrics, gates, failures, and outcome. Direct counterexamples against the checked-in baseline were all accepted: changing the outcome to `completed_pass` while retaining 46 failures; replacing all eight targets with duplicates of the first target; and setting a gate to `observed=0.0, passed=true`. A modified canonical artifact can therefore pass the documented strict-loader/closeout path while silently relabeling a failed run or drifting accepted thresholds.

**Fix:** Add after-validation that requires `targets == FORMAT_PARITY_TARGETS`, requires exactly one gate corresponding to each target with identical metric/operator/target, validates `passed` from `observed`, and enforces `completed_pass` only when every case and gate passes. Where a gate cannot be recomputed from `case_rows`, persist the underlying parser aggregate needed to validate its observed value. Add tamper tests for outcome, target duplication/value drift, gate contradiction, and aggregate drift.

```python
if self.targets != FORMAT_PARITY_TARGETS:
    raise ValueError("target_profile_mismatch")
if tuple((g.metric, g.operator, g.target) for g in self.gates) != tuple(
    (t.metric, t.operator, t.target) for t in FORMAT_PARITY_TARGETS.gates
):
    raise ValueError("gate_profile_mismatch")
if self.outcome is EvaluationOutcome.COMPLETED_PASS and (
    self.failures or any(gate.passed is not True for gate in self.gates)
):
    raise ValueError("completed_pass_has_failures")
```

### WR-04: Same-token recovery fails after the Markdown round reaches a terminal state

**File:** `scripts/eval_rag_format_parity.py:660-716`; `src/rag/evaluation/retrieval_rounds.py:298-348`

**Issue:** `_claim_or_resume()` accepts an active row only when `round_format == "markdown"` and otherwise always creates the deterministic Markdown token. After Markdown cleanup commits, a crash before the digital-PDF row is created leaves no active row; restart attempts to recreate the already-used unique Markdown `round_token` and returns `active_round_conflict`. A crash after the digital/scanned row is created leaves an active non-Markdown row that restart rejects as `active_round_mismatch`. Thus the advertised same-token recovery works only inside the first format, not across the three-round run.

**Fix:** Resolve all rows for the exact run token, validate their deterministic format order and terminal proofs, return the sole compatible active row regardless of format, and create only the first missing next-format row when all preceding rows are terminal-compatible. Add crash-window tests immediately before and after each next-round creation.

```python
rows = await repository.lock_run_rows(run_token)
state = validate_round_sequence(rows, expected_rollout_version=expected_rollout_version)
if state.active is not None:
    return state.active
return await repository.create_round(round_format=state.next_format, ...)
```

### WR-05: Retrieval-ready and cleanup proofs do not revalidate the exact recorded projection

**File:** `src/repositories/rag_evaluation_round_repo.py:339-370, 430-468`

**Issue:** Each successful attempt records a `doc_key -> head_id` mapping, but `prove_retrieval_ready()` ignores it and checks only three heads plus aggregate positive block/chunk counts. It does not prove that every expected head is the head accepted by this round, that every policy has blocks/chunks, or that its source checksum still matches the current format. `cleanup_current_projection()` likewise deletes children of whichever heads exist at cleanup time without comparing them to the recorded mapping. An interleaving replacement can preserve aggregate counts, be searched as if it belonged to this round, and then have its current children deleted. This violates the plan's exact same-token revalidation requirement.

**Fix:** Persist an exact per-document projection proof containing at least head ID and expected source checksum. At retrieval-ready and before any cleanup mutation, lock the heads and compare all three keys, IDs, checksums, per-head block/chunk counts, and canonical binding counts to that proof. On any drift, return `execution_error` without deleting the new projection. Add replacement and mixed-format interleaving tests.

```python
proof = parse_projection_proof(row.head_mappings_json)
for head in heads:
    expected = proof[head.doc_key]
    if str(head.id) != expected.head_id or head.source_checksum != expected.source_checksum:
        raise EvaluationIsolationError("projection_drift")
await self._prove_each_head_complete(heads)
```

### WR-06: Orphan ingestion jobs are invisible when the evaluation tenant has no heads

**File:** `src/repositories/rag_evaluation_round_repo.py:616-656`

**Issue:** `_current_counts()` returns zero for jobs before querying `rag_ingestion_jobs` whenever `heads` is empty. A NULL-document or stale failed job for one of the fixed document keys can therefore survive both `prove_compatible_pre_state()` and post-cleanup proof while the round records a clean state. The job table permits these job-only states, so absence of a `PolicyDocument` does not imply absence of evaluation jobs.

**Fix:** Count jobs by the fixed tenant and exact document-key allowlist unconditionally; only block/chunk queries should depend on `document_ids`. Add pre-state and post-cleanup tests with no heads and one NULL-document job.

```python
jobs = await self._count_allowed_evaluation_jobs()
if not document_ids:
    return {"documents": 0, "blocks": 0, "chunks": 0, "jobs": jobs}
```

### WR-07: Missing or unreadable contract files are mislabeled as unavailable prerequisites

**File:** `scripts/eval_rag_format_parity.py:262-284, 351-380`

**Issue:** Both provider entry points translate `manifest_file_invalid`, `gold_file_invalid`, and `fixture_file_invalid` to `unavailable_prerequisite`. Phase 64.3's accepted outcome taxonomy defines contract failure as `execution_error`; unavailable is reserved for DB/provider/OCR/config/runtime prerequisites. The current branch hides a broken or missing checked-in evaluation contract behind an infrastructure outcome, making operator diagnosis and closeout semantics incorrect (although it correctly avoids writing a baseline).

**Fix:** Map every `FormatParityContractError`, including file/read/hash failures, to a safe `execution_error` reason such as `evaluation_contract_invalid`. Keep `unavailable_prerequisite` only for independently checked runtime prerequisites. Add missing-manifest, missing-Gold, unreadable-fixture, and checksum-failure CLI tests for both provider modes.

```python
except FormatParityContractError:
    return build_diagnostic(
        dataset=_empty_dataset(),
        outcome=EvaluationOutcome.EXECUTION_ERROR,
        reason_codes=("evaluation_contract_invalid",),
        ...,
    )
```
