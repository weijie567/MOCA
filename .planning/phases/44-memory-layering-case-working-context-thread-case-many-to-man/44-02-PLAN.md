<objective>
Build the MEM-01 service layer against the migrated tables: (1) the mandatory B2 case-identity
resolver that turns the tool-layer `refund_case_no` string (and the free-form
`conversation_threads.case_id`) into the canonical `refund_cases.id` UUID; (2) typed CWC content
schemas with claim/fact separation; (3) a repository that reads the active CWC by case and writes a
new version while appending the prior content as an append-only revision row (B5).

Purpose: A join/scope key with no resolver, or a "versioned" table with no revision writer, are the
exact empty-machine failure modes 44-RESEARCH §1.1 warns about. This plan makes the identity and
versioning real before any lifecycle wiring.
Output: case_identity.py resolver, CWC schemas, CWC repository, and unit/DB tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tool layer (string case ref) → CWC scope key | untrusted/ambiguous string must resolve to a real UUID |
| write candidate → active CWC row | concurrent writers may race on the single active row |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-44-06 | Spoofing | resolve_case_id | mitigate | tenant-scoped lookup; a case_no from another tenant returns not_found |
| T-44-07 | Tampering | claim→fact promotion | mitigate | distinct pydantic types on distinct fields; a claim cannot silently become a verified_fact (D-CWC-3) |
| T-44-08 | Tampering | concurrent CWC write | mitigate | expected_version CAS check returns conflict instead of clobbering |
| T-44-09 | Repudiation | version history loss | mitigate | prior content snapshotted to append-only revisions before each update (B5) |
| T-44-10 | Elevation | authority escalation | accept | authority_class fixed at 'contextual_only' by 44-01 CHECK; repo cannot widen it |
</threat_model>
