# 08-04 PLAN: State + Node + Consumer Migration to KnowledgeService

<objective>
Switch the runtime path from the direct `search_policy` call to `PolicyKnowledgeService.search(...)` and migrate state/consumers to canonical `EvidenceRefV1` (D-A3, D-A4, D-B4, D-C2, D-D2). Specifically:

1. Migrate `src/agent/state.py` `EvidenceRef` TypedDict to the full EvidenceRefV1 field set.
2. Change the `evidence_refs` merge key from `(doc_key, chunk_id)` to `evidence_id` in `retrieve_policy_evidence._merge_evidence_refs`.
3. Switch `retrieve_policy_evidence` to build a `KnowledgeContext` (effective_at = run start), call the facade, and map `knowledge_search_result.v2` into AgentState.
4. Update `generate_recommendation` to emit structured material claims carrying `evidence_id`, run the new `validate_membership` (08-03), and keep merged refs consistent.
5. Keep `final_response` citation rendering working against migrated refs.

This is the only Phase 8 plan that changes runtime behavior. It must preserve existing strong/partial/no_evidence routing and the insufficient-evidence / retrieval-error drafts. Rollback is git revert (the adapter + legacy `search_policy` remain intact). No schema migration, no graph topology change.
</objective>

## Spec consistency findings
- `merchant_scope` and `trace_id` are NOT currently AgentState fields (verified in `src/agent/state.py`), and run-start time is not persisted (only `current_run_id` + a local `started_at` in `receive_request`). The node therefore constructs `KnowledgeContext` from available trusted sources: `tenant_id/user_id/role` from state, `run_id` from `current_run_id`, `trace_id` defaulted to `current_run_id` if no dedicated trace id exists, `merchant_scope` from the authz/session boundary if available else `None`, and `effective_at` = run-start timestamp computed once at the node entry. This is recorded as a Spec Consistency Finding; full TrustedContext convergence (incl. dedicated trace_id/merchant_scope plumbing) is owned by Phase 10. Phase 8 must not invent unauthorized scope.

## Schema/migration owner
- N/A with reason: no DB schema/migration. `EvidenceRef` is a `TypedDict` in `src/agent/state.py`, an in-memory contract, not a table. The checkpointer stores whatever dict shape the node emits.

## Service/API owner
- No API route change. The graph node now depends on `PolicyKnowledgeService` (Phase 8). `assess_risk_and_approval` and `final_response` consume migrated refs (see State/router impact).

## State/router impact
- `AgentState.evidence_refs` element shape changes from `(doc_key, chunk_id, title, confidence, retrieved_at)` to EvidenceRefV1 fields. Merge identity changes to `evidence_id`. `retrieved_evidence` now holds the `knowledge_search_result.v2` payload. Router decisions (no_evidence → insufficient draft; error → retrieval_error) are PRESERVED. `final_response._citation_summary` must continue to render (it reads `doc_key`/`chunk_id` which remain; `title`/`section` are no longer on the ref — handle with safe fallback).
