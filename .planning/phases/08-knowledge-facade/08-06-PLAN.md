# 08-06 PLAN: Observability Consumer Migration (trace + run API)

<objective>
Migrate the observability/reporting consumers that read the OLD retrieval payload shape so they keep working after 08-04 switches `retrieved_evidence` to `knowledge_search_result.v2` and `evidence_refs` to canonical `EvidenceRefV1` (merged by `evidence_id`). Two confirmed silent-failure sites (Codex review):

1. `src/agent/trace.py` `summarize_trace` (line ~201-203) computes `evidence_count` from `retrieval_data.get("evidence")`. Under v2 the key is `evidence_refs`, so the count silently becomes `0`.
2. `src/api/routers/agent_runs.py` `_extract_step_payload` (line ~472-476) computes `evidence_count` the same way (silent `0`), AND `_dedupe_evidence_refs` (line ~498-512) dedupes by bare `chunk_id`, which collapses distinct policy versions after the runtime merge key changed to `evidence_id`.

This is a pure reporting-layer migration. No runtime agent behavior, schema, or graph change. It depends on 08-04 (which produces the v2 shape) and runs in wave 4 (parallel with 08-05).
</objective>

This plan migrates them to read `evidence_refs` (with a legacy `evidence` fallback) and dedupe by `evidence_id` (with `chunk_id` fallback for legacy rows). Recorded in `08-EVAL-GATE.md` at 08-05.
