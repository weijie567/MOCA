<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Authenticated approval API -> ApprovalService | User/API input becomes trusted command only after auth, role, version, hash, and assignment validation. |
| ApprovalService -> graph resume | Server-constructed trusted approval result crosses into LangGraph resume state. |
| Ordinary chat -> safety/intent routing | Untrusted text must not be interpreted as approval authority. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-57-03-01 | Spoofing | ordinary chat approval text | mitigate | Preserve safety-pre-route and intent tests that keep approval-like chat unsupported/untrusted before `approval_gate` or `action_draft`. |
| T-57-03-02 | Tampering | API retry reconstruction | mitigate | Validate edited action, new action payload hash, expected versions, and allowed resume routes; legacy route is read-only historical compatibility marked `DELETE_BY_PHASE_58`. |
| T-57-03-03 | Elevation of privilege | approval edit rerisk | mitigate | Edit/superseded decisions route to `risk_gate`, never directly to `action_draft`. |
| T-57-03-04 | Repudiation | approval resume audit trail | mitigate | Preserve ApprovalService events and API response echo of canonical `resume_route`, while retaining explicit legacy retry test coverage. |
| T-57-03-05 | Tampering | trusted result schema | mitigate | Continue using `TrustedApprovalResultV1.model_validate` and tenant/run binding checks in route_after_approval. |
</threat_model>
