# Phase 24.3 Plan: Memory Write Isolation Policy and Observability MVP

## Objective

Extract and enforce the rule that memory side effects must not rollback or otherwise contaminate the main business transaction, and add minimal safe trace metrics for finalizer memory writes.

## Tasks

1. Add a small isolation helper that runs an async side effect in an independent `AsyncSession` derived from a parent session bind.
2. Refactor `/agent-runs` completed finalizer memory write to use the helper instead of inline session-factory code.
3. Add safe finalizer trace metrics for duration, slot count, fallback reason, reason code, and PII/write decision fields.
4. Add regressions proving:
   - isolated helper rolls back only the child session when the side effect fails.
   - finalizer trace metrics include the new safe observability fields.
   - existing rollback isolation regression still passes.

## Non-Goals

- No memory write behavior change beyond transaction isolation helper usage.
- No raw content telemetry.
- No schema migration.
