<threat_model>
## Trust Boundaries

| Boundary | Description |
| --- | --- |
| LLM structured output -> effective intent decision | Model output is candidate-only and cannot own effective route/risk/required-slot policy. |
| registry policy -> router edge key | Registry values must still pass deterministic finite router output validation. |
| chat text -> approval/action semantics | Approval-like ordinary chat cannot create approval/action authority. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- |
| T-32-02-01 | Elevation of Privilege / Spoofing | `classify_intent` | mitigate | Preserve candidate-only raw LLM output and record deterministic `policy_owner="IntentPolicyRegistry"` in classification trace. |
| T-32-02-02 | Tampering | `route_after_intent` | mitigate | Route decisions consume registry API then pass through existing finite legacy route-key guard. |
| T-32-02-03 | Elevation of Privilege | approval-like chat and short replies | mitigate | Keep Phase 25 fail-closed tests for approval-chat, safety-sensitive, low-confidence, and ambiguous short-reply paths. |
</threat_model>
