<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| rewrite planner -> retrieval channels | Internal rewrite expressions cause additional repository calls and must reuse trusted filters. |
| retrieval candidates -> EvidenceRefV1 | Candidates become canonical evidence refs only after merge/rank and must not carry diagnostics into identity. |
| retriever -> service facade | Safe query rewrite summary may be copied to `KnowledgeSearchResult`; raw diagnostics may not. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-03-01 | Elevation of privilege | rewrite channels | mitigate | Task 1 and Task 3 require identical tenant/doc/risk/effective-date filters for every channel and preserve service merchant-scope deny-all behavior. |
| T-23-03-02 | Tampering | candidate merge/dedupe | mitigate | Task 2 dedupes by `_candidate_key()` before final ranking and before `EvidenceRefV1.build()`. |
| T-23-03-03 | Information disclosure | selected_by/query_rewrite diagnostics | mitigate | Task 2 uses safe channel labels only; Task 3 exposes only safe summary. |
| T-23-03-04 | Denial of service | rewrite fan-out | mitigate | Task 2 enforces query/channel/candidate caps and safe fallback reasons. |
</threat_model>
