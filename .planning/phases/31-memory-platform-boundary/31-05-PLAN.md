<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| TrustedContext -> reviewed memory service | Trusted tenant/user/merchant/resource scope controls reviewed memory retrieval. |
| memory lifecycle services -> prompt projection | Only reviewed, prompt-safe, unexpired, non-deleted, non-tombstoned memory can become contextual prompt input. |
| target node -> legacy aliases | Legacy `long_term_memory` / `case_memory` aliases must mirror guarded target output, not bypass it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-cross-merchant | I | `reviewed_memory_context_retrieve` | mitigate | Trusted merchant scope is required; denied merchants produce empty bundle and filter reasons. |
| T-31-authority-forgery | S/T | memory_context bundle | mitigate | Output refs/status carry `authority_class="contextual_only"` and projection emits no authority refs. |
| T-31-pii-leakage | I | reviewed memory projection | mitigate | Existing lifecycle filters plus projector sanitization exclude non-prompt-safe PII/raw/private markers. |
| T-31-tombstone-revival | T/R | long-term/case retrieval | mitigate | Existing service tombstone filters remain the only retrieval source; tests prove tombstoned/deleted items do not surface. |
| T-31-replay-confusion | R/T | retrieve status refs | mitigate | Status refs are returned as contextual-only `reviewed_memory_context_retrieve_status.v1`, not replay events. |
| T-31-write-rollback | D/T | reviewed retrieval | accept | This plan reads memory only; write rollback is mitigated in Plan 31-06. |
</threat_model>
