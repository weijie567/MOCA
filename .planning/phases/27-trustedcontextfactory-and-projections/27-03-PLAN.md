<threat_model>
This plan extends the centralized threat model from 27-02 with seam-specific risks.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client request -> route trusted_context | Request payload/query cannot override identity, permissions, or merchant_scope. |
| route graph config -> graph nodes | Nodes must trust only `configurable["trusted_context"]` for service context authority. |
| AgentState checkpoint -> service projections | Checkpointed state cannot become permission or merchant-scope authority. |
| ToolCallContext -> KnowledgeContext | Knowledge projection must preserve authorized merchant scope and deny-before-query behavior. |
| approval/replay regression gates | Context projection metadata must not alter approval truth or replay event truth. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-03-01 | Spoofing / Elevation of Privilege | search and agent routes | mitigate | Routes create TrustedContext from authenticated/server inputs and tests include override attempts. |
| T-27-03-02 | Elevation of Privilege | investigate/action_draft nodes | mitigate | Nodes validate trusted graph config and grep/tests forbid permission or merchant_scope reads from AgentState. |
| T-27-03-03 | Information Disclosure | KnowledgeToolExecutor | mitigate | Central projection preserves list merchant_scope and knowledge service denies unauthorized merchant filters before adapter query. |
| T-27-03-04 | Tampering | compatibility graph config keys | mitigate | Compatibility keys remain outputs derived from canonical trusted_context, not independent trust roots. |
| T-27-03-05 | Tampering / Repudiation | approval/replay-adjacent projections | mitigate | `tests/test_approval_api.py` and `tests/replay/test_replay_service.py` run in focused gates to catch approval/replay regressions without changing those services. |
</threat_model>
