
<threat_model>
## Trust Boundaries

| Boundary | Description |
| --- | --- |
| recommendation_generation -> claim_verify | LLM-generated recommendations and claims cross into deterministic verification. |
| claim_verify -> risk/action | Only verified action-supporting claims may reach risk and action paths. |
| semantic provider -> bundle | Semantic review is untrusted relative to hard gates. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- |
| T-33-03-01 | Tampering | `generate_recommendation` | mitigate | static and unit tests prove generation writes material claims only and cannot set package/bundle verification fields. |
| T-33-03-02 | Spoofing / Elevation of privilege | business fact claims | mitigate | `claim_verify` requires `BusinessFactRefV1` and rejects RAG, memory, model, prompt summary, user text, and raw rows as current business authority. |
| T-33-03-03 | Tampering | semantic review | mitigate | DomainRuleVerifier hard checks run before semantic review and semantic pass cannot override failed hard gates. |
| T-33-03-04 | Elevation of privilege | `route_after_claim_verify` | mitigate | unsupported user-visible/action claims route to `final_response`; only verified bundles can route toward `assess_risk_and_approval`. |
| T-33-03-05 | Repudiation | bundle aggregation | mitigate | `ClaimVerificationBundleV1` records claim-level results, blocked claim IDs, safe support refs, and reason codes for audit. |
</threat_model>
