## Accomplishments

- Added strict `ToolArgumentSummaryV1`, `ToolResultStorageV1`, and `ToolResultPromptSummary` contracts.
- Added repository/service APIs for `tool_calls` and `tool_results` that keep argument hash, raw result ref/hash, normalized JSON, persisted summary, and prompt summary separate.
- Wired investigate to persist tool calls/results when a DB session is available and to return prompt-safe tool result refs/summaries in AgentState.
- Added tests proving large nested raw payload markers do not appear in prompt summaries or investigate state projections.

## Decisions Made

- Wired persistence in `investigate` rather than `ToolManager.invoke()` because investigate has access to `RunnableConfig.configurable["session"]`.
- Kept `raw_result_ref` and `raw_result_hash` nullable in runtime wiring; Plan 02 does not introduce a raw payload store.
- Used key-only argument summaries plus a stable hash of raw arguments so audit can detect argument changes without storing raw args.
- Preserved internal use of `ToolResultV2.data` for routing and business facts, but projected only refs/summaries into `state["tool_results"]`.
