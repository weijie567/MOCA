# Phase 15.1 Post-Review Fix Report

## Confirmed Findings Fixed

1. `src/db/migrations/versions/012_thread_user_scope.py` downgrade restored the legacy active `(tenant_id, thread_id)` unique index without checking for legal post-upgrade data where different users in the same tenant reuse a `thread_id`.
   - Fix: downgrade now runs an active duplicate preflight and fails fast with a cleanup instruction before dropping the user-scoped index.
   - Regression: `tests/conversation/test_models.py::test_thread_user_scope_migration_downgrade_fails_on_active_duplicate_threads`.

2. `src/conversation/repository.py` used select-then-insert for first conversation thread creation, so concurrent first messages for the same `(tenant_id, user_id, thread_id)` could race before the existing row lock path applied.
   - Fix: `get_or_create_thread()` now takes a transaction-scoped PostgreSQL advisory lock keyed by `(tenant_id, user_id, thread_id)` before selecting or creating the thread.
   - Regression: `tests/conversation/test_repository.py::test_concurrent_first_message_append_reuses_single_thread`.

## Not Changed

The interrupt-path persistence concern remains a separate verification item. It was not fixed in this commit because the review marked it as needing further validation rather than a confirmed bug.
