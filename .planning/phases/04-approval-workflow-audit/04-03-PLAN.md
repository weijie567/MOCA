<objective>
Implement the approval_gate node (interrupt/resume), execute_action node (write tool orchestration), write tool (create_coupon_grant_draft), update final_response for approval outcomes, and rewire the graph from linear to conditional topology. This is the core approval workflow implementation.

Key corrections from Codex review:
- approval_gate uses interrupt() correctly — return value IS the resume payload
- execute_action uses RunnableConfig pattern (not keyword session arg)
- final_response updated to handle approved/rejected/action outcomes
- Graph resumes on BOTH approve and reject (reject routes to final_response)
</objective>

<threat_model>
- **T-01 (High):** Bypassing approval gate — mitigated by conditional edge routing: if risk_assessment.approval_required is True, the ONLY path is through approval_gate. No edge skips it.
- **T-02 (High):** Executing action without approval — mitigated by execute_action checking approval_result.decision == "approve" before calling write tool
- **T-03 (Medium):** Forged resume payload — mitigated by approval API validating approval_id exists and matches the run before resuming
- Severity: high (T-01, T-02 are critical safety gates)
</threat_model>

Create `src/agent/nodes/approval_gate.py`:

```python
from __future__ import annotations

from datetime import UTC, datetime, timedelta
from typing import Any

from langgraph.types import interrupt

from src.agent.state import AgentState

APPROVAL_TIMEOUT_HOURS = 24


def _now_iso() -> str:
    return datetime.now(UTC).isoformat()


def _trace_step(status: str, started_at: str) -> dict[str, Any]:
    return {
        "node": "approval_gate",
        "status": status,
        "started_at": started_at,
        "completed_at": _now_iso(),
    }


async def approval_gate(state: AgentState) -> dict:
    """Interrupt graph for human approval. Resume payload becomes approval_result."""
    started_at = _now_iso()
    risk = state.get("risk_assessment") or {}
    proposed = state.get("proposed_action") or {}

    interrupt_payload = {
        "run_id": state.get("current_run_id"),
        "tenant_id": state.get("tenant_id"),
        "user_id": state.get("user_id"),
        "proposed_action": proposed,
        "risk_level": risk.get("risk_level"),
        "risk_reason": risk.get("risk_reason"),
        "risk_rule_ref": risk.get("rule_ref"),
        "expires_at": (datetime.now(UTC) + timedelta(hours=APPROVAL_TIMEOUT_HOURS)).isoformat(),
    }

    # interrupt() pauses here. Checkpointer saves state.
    # When resumed via Command(resume=decision_payload), `decision` receives that payload.
    # The approval API creates the approval_request record BEFORE resuming,
    # so the resume payload includes the approval_id for validation.
    decision = interrupt(interrupt_payload)

    # Expected decision shape:
    # {"approval_id": str, "decision": "approve"|"reject", "reason": str|None, "decided_by": str, "decided_at": str}

    return {
        "approval_result": decision,
        "trace_steps": (state.get("trace_steps") or []) + [_trace_step("completed", started_at)],
    }
```

Design notes:
- Node does NOT write to DB — the chat endpoint creates the approval_request when it detects the interrupt
- The `decision` variable receives whatever is passed via `Command(resume=...)`
- After resume, the node stores the decision in state and returns
- Both approve AND reject resume the graph — routing happens via conditional edge after this node
</action>

```python
from __future__ import annotations

from uuid import UUID

from sqlalchemy.ext.asyncio import AsyncSession

from src.repositories.action_draft_repo import ActionDraftRepository


def _tool_success(data: dict) -> dict:
    return {"status": "success", "data": data, "error": {}}


def _tool_error(error_code: str, message: str, retryable: bool) -> dict:
    return {"status": "error", "data": {}, "error": {"error_code": error_code, "message": message, "retryable": retryable}}


async def create_coupon_grant_draft(
    *,
    tenant_id: str,
    user_id: str,
    run_id: str,
    approval_request_id: str | None,
    idempotency_key: str,
    action_type: str,
    payload: dict,
    session: AsyncSession,
) -> dict:
    try:
        repo = ActionDraftRepository(session)
        draft, created = await repo.create_or_get(
            run_id=UUID(run_id),
            tenant_id=UUID(tenant_id),
            approval_request_id=UUID(approval_request_id) if approval_request_id else None,
            idempotency_key=idempotency_key,
            action_type=action_type,
            payload=payload,
        )
        return _tool_success({
            "draft_id": str(draft.id),
            "idempotency_key": draft.idempotency_key,
            "status": draft.status,
            "created": created,
            "idempotent_reused": not created,
        })
    except Exception as exc:
        return _tool_error("DRAFT_CREATION_FAILED", str(exc), retryable=True)
```

Note: `create_approval_request` tool from CONTEXT.md D-03f is NOT needed as a separate tool — the approval_request is created by the API layer (chat endpoint) when it detects the interrupt, not by a graph node. This avoids the non-idempotent DB write before interrupt() issue flagged by Codex.

```python
from __future__ import annotations

from datetime import UTC, datetime
from typing import Any

from langchain_core.runnables import RunnableConfig

from src.agent.state import AgentState
from src.agent.tools.create_coupon_grant_draft import create_coupon_grant_draft


def _now_iso() -> str:
    return datetime.now(UTC).isoformat()


def _trace_step(status: str, started_at: str, tool_name: str | None = None) -> dict[str, Any]:
    return {
        "node": "execute_action",
        "status": status,
        "started_at": started_at,
        "completed_at": _now_iso(),
        "tool_name": tool_name,
    }


async def execute_action(state: AgentState, config: RunnableConfig) -> dict:
    """Execute the approved action (create draft). Uses RunnableConfig for session access."""
    started_at = _now_iso()
    proposed = state.get("proposed_action") or {}
    approval = state.get("approval_result") or {}
    risk = state.get("risk_assessment") or {}

    # Safety check: if approval was required but not approved, do not execute
    if risk.get("approval_required") and approval.get("decision") != "approve":
        return {
            "action_result": {"status": "error", "data": {}, "error": {"error_code": "NOT_APPROVED", "message": "Action requires approval but was not approved"}},
            "trace_steps": (state.get("trace_steps") or []) + [_trace_step("error", started_at)],
        }

    # Get session from config (same pattern as existing nodes that need DB)
    session = config["configurable"]["session"]

    # Build idempotency key: run_id + approval_id + action_type + target_id
    approval_id = approval.get("approval_id") or "no_approval"
    idem_key = f"{state.get('current_run_id')}_{approval_id}_{proposed.get('action_type', 'unknown')}_{proposed.get('target_id', 'unknown')}"

    result = await create_coupon_grant_draft(
        tenant_id=state.get("tenant_id", ""),
        user_id=state.get("user_id", ""),
        run_id=state.get("current_run_id", ""),
        approval_request_id=approval.get("approval_id"),
        idempotency_key=idem_key,
        action_type=proposed.get("action_type", "unknown"),
        payload=proposed,
        session=session,
    )

    status = "completed" if result.get("status") == "success" else "error"
    return {
        "action_result": result,
        "trace_steps": (state.get("trace_steps") or []) + [_trace_step(status, started_at, "create_coupon_grant_draft")],
    }
```

Key: Uses `config: RunnableConfig` parameter (LangGraph passes this automatically to nodes that declare it). Session accessed via `config["configurable"]["session"]` — same pattern used by existing nodes.

```python
def route_after_risk(state: AgentState) -> str:
    """Route based on risk assessment and proposed action."""
    risk = state.get("risk_assessment") or {}
    proposed = state.get("proposed_action")
    if risk.get("approval_required"):
        return "approval_gate"
    if proposed:
        return "execute_action"
    return "final_response"


def route_after_approval(state: AgentState) -> str:
    """Route after approval decision. Both approve and reject resume here."""
    result = state.get("approval_result") or {}
    if result.get("decision") == "approve":
        return "execute_action"
    # reject → final_response (explains rejection to user)
    return "final_response"
```

4. Replace linear edge with conditional routing:
```python
# REMOVE: builder.add_edge("assess_risk_and_approval", "final_response")
# ADD:
builder.add_conditional_edges(
    "assess_risk_and_approval",
    route_after_risk,
    {"approval_gate": "approval_gate", "execute_action": "execute_action", "final_response": "final_response"},
)
builder.add_conditional_edges(
    "approval_gate",
    route_after_approval,
    {"execute_action": "execute_action", "final_response": "final_response"},
)
builder.add_edge("execute_action", "final_response")
```

5. Keep `builder.add_edge("final_response", END)` unchanged.

Backward compatibility: Phase 3 queries (policy_qa, insufficient_evidence) never set `proposed_action` and have `approval_required=False`, so they route directly to `final_response` — same as before.

Both approve and reject resume the graph through approval_gate → conditional edge. Approve routes to execute_action → final_response. Reject routes directly to final_response (which explains the rejection).
