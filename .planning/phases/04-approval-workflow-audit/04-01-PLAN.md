<objective>
Add per-node latency instrumentation (provider_latency_ms, retry_count, metrics_json) to all graph nodes and create a diagnostic script that analyzes agent_runs by run_id to identify bottleneck nodes. This is the Phase 4 prerequisite per ROADMAP — diagnose before optimizing.

Also extends receive_request to reset Phase 4 state fields (proposed_action, approval_result, action_result) to prevent stale state leakage across turns.
</objective>

<threat_model>
- No new attack surface — read-only diagnostic script, no external input
- metrics_json must NOT contain prompt text or sensitive data (D-01c)
- Severity: none applicable
</threat_model>

```python
provider_latency_ms: Mapped[int | None] = mapped_column()
```

<task id="01-02">
<title>Instrument all LLM nodes with provider_latency_ms and metrics_json</title>
<read_first>
- src/agent/nodes/assess_risk_and_approval.py
- src/agent/nodes/classify_intent.py
- src/agent/nodes/extract_slots.py
- src/agent/nodes/generate_recommendation.py
- src/agent/nodes/final_response.py
</read_first>
<action>
For each LLM node (classify_intent, extract_slots, generate_recommendation, assess_risk_and_approval, final_response), wrap the `ainvoke` call with timing:

```python
import time

t0 = time.perf_counter()
result = await structured_llm.ainvoke(messages)
provider_latency_ms = round((time.perf_counter() - t0) * 1000)
```

Update each node's `_trace_step()` helper to include:
```python
{
    "node": "node_name",
    "status": status,
    "started_at": started_at,
    "completed_at": _now_iso(),
    "model_name": settings.llm_model,
    "prompt_tokens": None,  # populated if available from response metadata
    "completion_tokens": None,
    "provider_latency_ms": provider_latency_ms,
    "retry_count": attempt,  # from the manual retry loop counter
    "metrics_json": {
        "model": settings.llm_model,
        "provider": "dashscope",
        "context_chars": len(str(messages)),
    },
}
```

Important: `retry_count` here refers to the node's internal retry loop (e.g., `for attempt in range(2)` in assess_risk_and_approval). This is distinct from LangGraph's graph-level RetryPolicy which re-runs the entire node. Document this distinction in a code comment.

For non-LLM nodes (receive_request, load_business_context, retrieve_policy_evidence), add node-level timing but set provider_latency_ms=None and metrics_json=None.
</action>

<action>
Add three new fields to the reset dict in `receive_request()`:

```python
return {
    # ... existing resets ...
    "proposed_action": None,
    "approval_result": None,
    "action_result": None,
```

<task id="01-04">
<title>Create diagnostic script scripts/diagnose_latency.py</title>
<read_first>
- src/db/models.py
- src/db/session.py
- src/agent/trace.py
</read_first>
<action>
Create `scripts/diagnose_latency.py` with:

1. CLI interface: `uv run python scripts/diagnose_latency.py --run-id <uuid>`
2. Connect to DB using existing session factory
3. Query agent_steps for the given run_id, ordered by step_index
4. Compute per-node: latency_ms, provider_latency_ms, retry_count, prompt_tokens, completion_tokens, context_chars (from metrics_json)
5. Identify bottleneck: node with highest latency_ms
6. Output JSON report:

```json
{
  "run_id": "...",
  "total_latency_ms": 95000,
  "node_count": 8,
  "nodes": [
    {
      "node": "classify_intent",
      "step_index": 1,
      "latency_ms": 12000,
      "provider_latency_ms": 11500,
      "retry_count": 0,
      "prompt_tokens": 450,
      "completion_tokens": 50,
      "context_chars": 2100
    }
  ],
  "bottleneck": {
    "node": "generate_recommendation",
    "latency_ms": 35000,
    "pct_of_total": 36.8
  },
  "suspected_causes": ["high provider latency on generate_recommendation", "retry detected on assess_risk_and_approval"]
}
```

7. Support `--mock` flag that generates a synthetic report without DB access (for CI)
8. Use argparse, no new dependencies
</action>
<acceptance_criteria>
- `scripts/diagnose_latency.py` exists and is executable with `uv run python scripts/diagnose_latency.py --help`
- Script accepts `--run-id` argument
- Script accepts `--mock` flag
- `--mock` flag outputs valid JSON with keys: run_id, total_latency_ms, nodes, bottleneck, suspected_causes
- Script imports from `src.db.models` and `src.db.session`
- No hardcoded DB credentials in script (uses existing config)
</acceptance_criteria>
</task>
