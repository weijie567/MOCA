## Warnings

### WR-01: Mixed malformed authoritative refs are silently dropped before promotion

**File:** `src/memory/case_working_context_lifecycle.py:592-621,757-781,1031-1035`

**Issue:** `_parse_business_refs()` and `_parse_policy_refs()` both iterate `_iter_mappings(value)`. For a list, `_iter_mappings()` returns only members that are mappings and silently discards every scalar or otherwise malformed member. A result such as `[valid_exact_ref, "malformed-member"]` therefore leaves `business_invalid`/`policy_invalid` false. For policy evidence, the new exact resolver validates the surviving ref and adds its ID to the global validated set; for business facts, the surviving typed ref already passes the existing gate. In both cases the result can remain `reference_validation="valid"` and be promoted even though the original authoritative-ref set was malformed. This contradicts the helper's stated complete-per-result guarantee and the fail-closed authority contract.

**Fix:** Validate the original container and preserve its cardinality before parsing. Treat every non-mapping member, failed model validation, and unexpected container shape as `refs_invalid=True`; only call the exact policy resolver when the complete original set parsed successfully. For example:

```python
def _raw_ref_members(value: Any) -> tuple[list[Mapping[str, Any]], bool]:
    if isinstance(value, Mapping):
        return [value], False
    if not isinstance(value, (list, tuple)):
        return [], value is not None
    members = list(value)
    return [item for item in members if isinstance(item, Mapping)], any(
        not isinstance(item, Mapping) for item in members
    )
```

Use the returned invalid flag in both parsers and add policy-evidence and business-fact negative tests containing one valid ref plus one malformed member. Assert that neither case enters `verified_facts` or promoted provenance.
