## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding within badges |
| sm | 8px | Compact element spacing, gap between timeline step icon and label |
| md | 16px | Default element spacing, card internal padding |
| lg | 24px | Section padding, column internal padding |
| xl | 32px | Layout gaps between the three columns |
| 2xl | 48px | Major section breaks (top-bar to content area) |
| 3xl | 64px | Page-level spacing (not used in this phase) |

Exceptions: Touch targets for Approve / Reject buttons minimum 44px height to meet WCAG 2.5.5.

Source: 8-point scale default. Exception derived from WCAG accessibility requirement for approval action buttons (FRNT-02).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 12px | 400 | 1.4 |
| Heading | 16px | 600 | 1.3 |
| Display | 20px | 600 | 1.2 |

Notes:
- Body (14px/400): chat message text, evidence chunk text, trace detail text.
- Label (12px/400): timeline step labels, badge text, tab labels, metadata fields (node_name, timestamp, risk_level). Differentiated from Body via smaller size (12px) and muted color (`hsl(215 16% 47%)`), not weight.
- Heading (16px/600): panel section headers ("Agent Timeline", "Evidence", "Approval", "Trace"), card titles.
- Display (20px/600): top-bar app title "Agent Workflow Console", role switcher current role name.

Weights in use: 400 (regular) and 600 (semibold) only.

Source: Claude's Discretion. Sized for dense three-column IDE-style layout (CONTEXT.md D-16, §Specific Ideas). Compact scale avoids overflow in 30/35/35 column split. Label weight reduced from 500 to 400 to stay within the two-weight maximum; visual distinction maintained via size and color.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(224 71% 4%)` — near-black | Page background, column backgrounds |
| Secondary (30%) | `hsl(215 28% 17%)` — dark slate | Cards, timeline container, right panel, top-bar |
| Accent (10%) | `hsl(217 91% 60%)` — blue-500 | See reserved list below |
| Destructive | `hsl(0 72% 51%)` — red-600 | Reject button, rejected status badge, error state border |

Accent reserved for:
1. "发送问题" (Submit) button in chat input — primary CTA only
2. Active/running timeline step indicator dot
3. Approve button in approval dialog
4. Active tab underline in right panel Tabs
5. "Demo Mode" role switcher highlight border

All other interactive elements (secondary buttons, tab triggers, hover states) use secondary surface color with border, not accent.

Source: Claude's Discretion. Dark theme chosen to match "clean, modern, similar to IDE layout" direction from CONTEXT.md §Specific Ideas. shadcn default dark preset maps cleanly to these HSL values. Accent is blue to align with "running/active" semantic in timeline.

Status color semantics (not part of 60/30/10 — used only in status badges):

| Status | Color | Badge variant |
|--------|-------|---------------|
| running | `hsl(217 91% 60%)` blue | outline |
| completed | `hsl(142 71% 45%)` green | default |
| waiting_approval | `hsl(38 92% 50%)` amber | outline |
| rejected | `hsl(0 72% 51%)` red | destructive |
| degraded | `hsl(38 92% 50%)` amber | outline |
| failed | `hsl(0 72% 51%)` red | destructive |
| disconnected | `hsl(215 16% 47%)` muted | secondary |

Source: CONTEXT.md D-23 defines the 7 status types. Color mapping is Claude's Discretion.

## Layout Contract

Three-column layout (desktop, min-width 1280px):

| Column | Width | Content |
|--------|-------|---------|
| Left | 30% | Chat panel: message history (ScrollArea), input Textarea, Submit button |
| Center | 35% | Agent Timeline: SSE-driven step list with status indicators |
| Right | 35% | Details panel: Tabs (Evidence / Approval / Trace / Run Info) |

Top bar (full width, 48px height): App title "Agent Workflow Console" + Demo Mode label + Role Switcher (Select).

Primary visual anchor: Center column Agent Timeline — user attention is drawn here during active runs via the animated status dot on the current step and the sequential step reveal as SSE events arrive.

Responsive fallback (< 1280px): collapse to two columns — Left chat panel (40%) + right combined Timeline/Details with internal Tab (60%). Not a Phase 5 priority per CONTEXT.md D-19.

Source: CONTEXT.md D-16, D-17, D-18, D-19.

## Component Interaction Contracts

### Chat Panel (Left)

- Message history: ScrollArea, auto-scrolls to bottom on new message.
- User messages: right-aligned, secondary surface background.
- Agent final response: left-aligned, Card with evidence citation list below message text.
- Evidence citation: each item shows `doc_id` + `chunk_id` + short excerpt as Label text.
- Input: Textarea (min 2 rows, max 6 rows auto-resize) + "发送问题" Button (accent, disabled while `status === 'running'`).
- While running: Skeleton placeholder in message list shows Agent is processing.

### Agent Timeline (Center)

- Ordered list of SSE steps, newest at bottom.
- Each step row: status dot (colored per status table) + Chinese message text + Label timestamp.
- Chinese status messages (from CONTEXT.md §Specific Ideas):
  - `classify_intent` → "正在识别意图"
  - `extract_slots` → "正在读取订单信息"
  - `retrieve_policy` → "正在检索退款规则"
  - `generate_recommendation` → "正在生成处理建议"
  - `assess_risk` → "正在判断风险等级"
  - `approval_gate` → "需要审批，等待人工决策"
  - `execute_action` → "正在执行操作"
  - `final_response` → "已完成"
- `approval_required` event: step row shows amber "需要审批" badge; right panel auto-switches to Approval Tab (CONTEXT.md D-17).
- `error` event: step row shows red "失败" badge.
- Disconnected state: banner above timeline "连接中断，正在恢复状态" (CONTEXT.md D-25).

### Details Panel — Approval Tab (Right)

- Shown automatically when `approval_required` SSE event arrives.
- Card shows: action type, risk level Badge, amount, order_id, reason summary.
- Two buttons: "批准" (accent, 44px min height) + "驳回" (destructive, 44px min height).
- Clicking either opens a Dialog for confirmation before calling the API.
- After decision: buttons disabled, status Badge updates to "已批准" or "已驳回".
- Post-approval: frontend polls `GET /api/v1/agent-runs/{run_id}` every 2 seconds until terminal state (CONTEXT.md D-15). Polling interval is Claude's Discretion.

### Details Panel — Evidence Tab (Right)

- List of evidence chunks from `GET /api/v1/agent-runs/{run_id}/evidence`.
- Each chunk: Card with doc_id, chunk_id, section title (Heading), excerpt text (Body), risk_level Badge.
- Empty state: "暂无证据" heading + "Agent 尚未检索到相关规则，请等待执行完成" body.

### Details Panel — Trace Tab (Right)

- Table or list of AgentStep records from `GET /api/v1/agent-runs/{run_id}/trace`.
- Each row: node_name, status Badge, latency_ms, error_message (if any).
- Error rows: red border-left on row, error_code + error_message in Label text.
- Source: CONTEXT.md D-28 — preserve detailed error info for interview explanation.

### Details Panel — Run Info Tab (Right)

- Key-value pairs: run_id, status Badge, created_at, tenant_id, user role.
- "Demo Mode" indicator Badge (amber, "演示模式").

### Role Switcher (Top Bar)

- Select component with options: "客服专员 (Support Agent)" / "审批员 (Approver)" / "管理员 (Admin)".
- On change: fetch demo JWT, update auth context, show Toast "已切换角色: {role}".
- Current role shown as Badge next to "Demo Mode" label.
- Source: CONTEXT.md D-20, D-21, D-22.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | 发送问题 |
| Chat empty state heading | 开始一个退款咨询 |
| Chat empty state body | 输入订单号或退款问题，Agent 将检索规则并给出处理建议。例如：请给 ORD-2024-001 补偿 600 元 |
| Evidence empty state heading | 暂无证据 |
| Evidence empty state body | Agent 尚未检索到相关规则，请等待执行完成 |
| Timeline empty state | 等待提交问题后开始执行 |
| Error state (LLM/tool failure) | 执行遇到问题，请重试。如问题持续，请联系管理员 |
| SSE disconnect banner | 连接中断，正在恢复状态 |
| Degraded state (no evidence) | 证据不足，无法给出确定性结论。建议补充以下信息：{missing_info list} |
| Approval rejected message | 审批已驳回：{rejection_reason}。本次操作已取消 |
| Approve confirmation dialog | 确认批准此操作？批准后 Agent 将继续执行，此操作不可撤销 |
| Reject confirmation dialog | 确认驳回此操作？驳回后 Agent 将停止执行并通知申请方 |
| Role switch Toast | 已切换角色：{role_name} |
| Submit disabled tooltip | Agent 正在处理中，请等待完成 |

Destructive actions in this phase:
1. Reject approval — Dialog confirmation required before calling API (copy above).
2. Approve high-risk action — Dialog confirmation required (copy above). Approve is not destructive in the traditional sense but is irreversible, so confirmation is required.

Source: CONTEXT.md D-24 through D-27 define error/status copy requirements. Chinese copy is Claude's Discretion within those constraints. Demo flow example from CONTEXT.md §Specific Ideas.
