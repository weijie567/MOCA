<objective>
Close the SSE duplicate execution gap from `05-VERIFICATION.md`.

Purpose: `/events` currently begins graph execution for any visible run and only marks the run `running` inside the generator. A retry or second tab can execute the same run twice. This plan makes run start a single atomic claim and returns `409 RUN_ALREADY_STARTED` for already-started or terminal runs.
Output: guarded backend SSE endpoint plus regression tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser/API client -> `/api/v1/agent-runs/{run_id}/events` | Untrusted run_id and bearer token request an execution-starting stream. |
| API -> LangGraph execution | Starting a stream can invoke tools, create approvals, and write trace/action rows. |
| API -> database | Run ownership, tenant_id, and final_status decide whether execution may begin. |
| Frontend container -> API service | Not changed in this plan, but duplicate-execution errors must not leak internal routing details. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-05-01 | S | `stream_agent_run_events` auth/RBAC | mitigate | Keep `Security(get_current_user, scopes=["agent:chat"])`; tests use bearer JWT with `agent:chat`. |
| T-05-05-02 | I | Token handling | mitigate | Do not accept query-string tokens; preserve Authorization-header-only SSE auth from Plan 01. |
| T-05-05-03 | T/D | SSE duplicate execution | mitigate | Add locked pending-to-running claim before `EventSourceResponse`; return `409 RUN_ALREADY_STARTED` for non-pending runs. |
| T-05-05-04 | I/E | Tenant isolation | mitigate | Claim query includes `AgentRun.tenant_id == user.tenant_id`; cross-tenant run_id returns 404 before status mutation. |
| T-05-05-05 | E | Approval authorization | mitigate | Prevent duplicate streams from creating duplicate pending approvals; approval decisions remain protected by existing `approvals:review` endpoint. |
| T-05-05-06 | I | Docker/API routing exposure | accept | No Docker routing files are touched; error responses use existing `ApiResponse` handler and do not expose service names. |
</threat_model>
