<task id="06.3">
<title>Prepend section heading to chunk content for embedding</title>
<read_first>
- src/rag/ingestion.py (where chunk content is passed to embedder)
- src/rag/chunker.py (ChunkResult has section field)
- src/rag/retriever.py (how chunks are returned)
</read_first>
<action>
Modify `src/rag/ingestion.py` to prepend the section heading to chunk content BEFORE embedding:

In the `ingest_document` method, change the embedding input from:
```python
texts = [c.content for c in chunks]
```
to:
```python
texts = [f"{c.section}：{c.content}" if c.section != "intro" else c.content for c in chunks]
```

This gives the embedding model more semantic context about what each chunk is about. The stored `PolicyChunk.content` remains unchanged (raw text without heading prefix) — only the embedding input gets the prefix.

Rationale: DashScope text-embedding-v4 benefits from contextual prefixes. A chunk containing "买家在签收商品后7天内可申请退款" embeds differently when prefixed with "七天无理由退款：" — the prefix disambiguates from similar text in other contexts.

Note: This requires re-ingestion after the change. The ingestion script is idempotent so re-running it will update embeddings.
</action>
<acceptance_criteria>
- src/rag/ingestion.py contains heading prefix logic for embedding input
- The prefix format is `f"{section}：{content}"` (Chinese colon separator)
- "intro" sections are NOT prefixed (they have no meaningful heading)
- PolicyChunk.content stored in DB remains the raw text (no heading prefix in stored content)
- After re-ingestion, embeddings reflect the prefixed text
</acceptance_criteria>
</task>

<task id="06.4">
<title>Add doc-level Hit metric to eval script</title>
<read_first>
- scripts/eval_rag_hit_at_5.py
</read_first>
<action>
Add a secondary metric `Doc-Hit@5` to the eval script that checks if ANY chunk from an expected document appears in top-5 results (regardless of exact chunk_id match). This helps distinguish between:
- "Wrong document retrieved" (both Hit@5 and Doc-Hit@5 fail) → embedding quality issue
- "Right document, wrong chunk" (Doc-Hit@5 passes, Hit@5 fails) → golden set calibration issue

Add to the eval loop:
```python
# After existing hit check:
retrieved_doc_keys = {e.doc_key for e in result.evidence}
expected_docs = set(case["expected_doc_ids"])
if expected_docs & retrieved_doc_keys:
    doc_hits += 1
```

Add to report output:
```
Doc-Hit@5: {doc_hit_at_5:.1%} (right document in top-5)
```

Doc-Hit@5 is informational only — does NOT affect exit code (only Hit@5 and fallback accuracy determine pass/fail).
</action>
<acceptance_criteria>
- scripts/eval_rag_hit_at_5.py prints `Doc-Hit@5` metric in report
- Doc-Hit@5 checks expected_doc_ids against retrieved doc_keys
- Doc-Hit@5 does NOT affect exit code (informational only)
- Both Hit@5 and Doc-Hit@5 are printed in the summary
</acceptance_criteria>
</task>
