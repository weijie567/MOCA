# Plan 07: Retrieval Quality — Embedding Context Enrichment + Threshold Tuning

<objective>
Raise Hit@5 from 58.3% to ≥80% through three retrieval quality improvements that address the actual semantic gap (not golden set calibration):
1. Prepend document title + section heading to embedding input (context enrichment)
2. Lower min_similarity_threshold from 0.55 to 0.45 (widen recall window)
3. Increase top_k from 5 to 10 internally, then re-rank and return top 5 (over-fetch + filter)

These are standard RAG retrieval improvements that don't change the architecture.
</objective>

<tasks>

<task id="07.1">
<title>Enrich embedding input with document title + section heading</title>
<read_first>
- src/rag/ingestion.py (line 50: current embedding input is raw chunk.content)
- src/rag/chunker.py (ChunkResult has doc_key and section fields)
- data/policies/refund_policy.md (see actual section headings)
</read_first>
<action>
Modify `src/rag/ingestion.py` line 50. Change:

```python
texts = [chunk.content for chunk in chunks]
```

to:

```python
texts = [
    f"{title} / {chunk.section}：{chunk.content}" if chunk.section != "intro" else f"{title}：{chunk.content}"
    for chunk in chunks
]
```

Where `title` is `doc_meta["title"]` (already available in scope at line 42).

This prepends the document title and section heading to the text sent to the embedding model. Examples:
- Before: `"买家在签收商品后7天内，如商品未经使用且不影响二次销售..."`
- After: `"退款规则 / 七天无理由退款：买家在签收商品后7天内，如商品未经使用且不影响二次销售..."`

The stored `PolicyChunk.content` in the database remains unchanged (raw text). Only the embedding vector reflects the enriched context.

Rationale: DashScope text-embedding-v4 is a general-purpose model. Without context, chunks about "退款时效" from different documents (refund_policy vs refund_time_limits) embed to very similar vectors. The title+heading prefix disambiguates them.
</action>
<acceptance_criteria>
- src/rag/ingestion.py embedding input includes document title and section heading
- Format is `f"{title} / {chunk.section}：{chunk.content}"` for non-intro chunks
- Format is `f"{title}：{chunk.content}"` for intro chunks
- PolicyChunk.content stored in DB is still raw text (no prefix)
- grep for `title` and `chunk.section` in the embedding text construction
</acceptance_criteria>
</task>

<task id="07.2">
<title>Lower min_similarity_threshold and add over-fetch strategy</title>
<read_first>
- src/rag/retriever.py (current thresholds: MIN=0.55, STRONG=0.70)
- src/repositories/policy_chunk_repo.py (search_similar top_k parameter)
</read_first>
<action>
Modify `src/rag/retriever.py`:

1. Lower the internal retrieval threshold to cast a wider net:
```python
INTERNAL_SEARCH_THRESHOLD = 0.40  # wider net for initial retrieval
MIN_SIMILARITY_THRESHOLD = 0.55   # still the user-facing cutoff for "evidence exists"
STRONG_EVIDENCE_THRESHOLD = 0.70
```

2. In the `search` method, over-fetch then filter:
```python
async def search(self, query, tenant_id, top_k=5, ...):
    query_embedding = await self.embedder.embed_query(query)

    # Over-fetch: retrieve 2x candidates with lower threshold
    raw_results = await self.chunk_repo.search_similar(
        query_embedding=query_embedding,
        tenant_id=tenant_id,
        top_k=top_k * 2,  # fetch 10 candidates
        min_similarity=INTERNAL_SEARCH_THRESHOLD,  # 0.40 instead of 0.55
        doc_type=doc_type,
        risk_level=risk_level,
    )

    # Filter to user-facing threshold and limit
    results = [(chunk, score) for chunk, score in raw_results if score >= MIN_SIMILARITY_THRESHOLD][:top_k]

    # Build evidence from filtered results...
```

This means:
- pgvector returns up to 10 candidates above 0.40 similarity
- We filter to those above 0.55 and take top 5
- The wider initial net catches chunks that are semantically relevant but scored just below 0.55 due to embedding noise
- User-facing behavior unchanged: evidence items still only show score >= 0.55
</action>
<acceptance_criteria>
- src/rag/retriever.py contains `INTERNAL_SEARCH_THRESHOLD = 0.40`
- src/rag/retriever.py passes `top_k * 2` to search_similar (over-fetch)
- src/rag/retriever.py passes `INTERNAL_SEARCH_THRESHOLD` (not MIN_SIMILARITY_THRESHOLD) to search_similar
- Post-filter still applies MIN_SIMILARITY_THRESHOLD = 0.55 before building evidence
- Final evidence list is limited to original top_k (5)
</acceptance_criteria>
</task>

<task id="07.3">
<title>Enrich query embedding with context hint</title>
<read_first>
- src/rag/embedder.py (embed_query method)
- src/rag/retriever.py (where embed_query is called)
</read_first>
<action>
Modify `src/rag/retriever.py` to prepend a domain context hint to the query before embedding:

```python
QUERY_PREFIX = "电商退款规则查询："

async def search(self, query, ...):
    enriched_query = f"{QUERY_PREFIX}{query}"
    query_embedding = await self.embedder.embed_query(enriched_query)
    ...
```

This aligns the query embedding space with the document embeddings (which now have title/section prefixes). Without this, there's an asymmetry: documents are embedded with rich context but queries are bare text.

The prefix is short and domain-specific. It tells the embedding model "this is a query about e-commerce refund rules" which helps it weight relevant dimensions.
</action>
