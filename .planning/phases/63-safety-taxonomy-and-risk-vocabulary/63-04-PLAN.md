<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ordinary chat text -> pre-route policy | User text can look like approval/action commands but must not become trusted approval truth. |
| intent definitions -> runtime routing | Runtime routing must follow registry-owned safety policy rather than drift-prone fallback sets. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-63-13 | Spoofing | `detect_pre_route` | mitigate | Preserve approval-chat-not-trusted and policy-question hard-negative checks before taxonomy action keyword matching. |
| T-63-14 | Elevation of Privilege | `_action_bound_or_high_risk` | mitigate | Derive action/high-risk behavior from registry and fail closed on invalid registry behavior. |
| T-63-15 | Tampering | `_policy_evidence_required` | mitigate | Use registry definition-owned evidence requirements after trusted overrides; tests cover derivation. |
| T-63-16 | Denial of Service | registry exceptions | mitigate | Routing helpers must catch/handle invalid registry behavior by routing to clarification/fail-closed paths, not unsafe action paths. |
</threat_model>
