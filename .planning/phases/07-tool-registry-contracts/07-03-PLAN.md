<objective>
Add compatibility-preserving adapters and prompt-facing sanitization over the safe registry boundary.

Purpose: let Phase 7 invoke the existing read/retrieval tools through typed adapters while preserving direct-call compatibility and preventing raw payload leakage into investigator-facing results.
Output: `src/agent/tools/adapters.py`, adapter/registry sanitization coverage in `tests/agent/test_tools/test_tool_adapters.py`, and any minimal registry test extension needed to prove prompt-facing sanitization behavior.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| typed adapter input -> existing tool function | Validated adapter inputs must forward into the unchanged underlying tool signatures without bypassing existing authz or tenant scoping. |
| raw tool result -> ToolExecutionResult summary | Internal `data` payloads, especially policy evidence `text`, must not leak into prompt-facing outputs. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-07 | T | adapter forwarding layer | mitigate | Wrap existing `get_order`, `get_refund_case`, `get_ticket`, and `search_policy` signatures instead of changing them, preserving direct-call behavior per REG-06 boundary and D-03. |
| T-07-08 | I | prompt-facing sanitization | mitigate | Summarize success results with only declared `result_summary_fields` plus `status`, `error`, and `evidence_refs`; do not expose raw `data` or policy evidence `text`, per REG-08 and D-11. |
| T-07-09 | E | authz bypass via adapter | mitigate | Adapters must delegate to existing tool functions with `tenant_id`, `user_id`, `role`, and `session` from context so current authorization remains authoritative. |
</threat_model>
