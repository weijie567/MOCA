<objective>
Build the safe registry boundary that validates definitions and rejects unsafe investigator requests before any underlying tool executes.

Purpose: convert the contract layer into an enforceable allowlist and invocation boundary without changing existing graph/runtime wiring.
Output: `src/agent/tools/registry.py` with fail-fast validation and caller-aware invocation policy, plus `tests/agent/test_tools/test_registry.py` covering exact allowlist, unsafe exclusions, and non-execution guarantees.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| requested tool name/input -> registry policy | Untrusted invocation requests must be checked before any adapter or tool function runs. |
| registry definition creation -> runtime execution | Unsafe or incomplete metadata must fail construction before the runtime can expose it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-04 | E | investigator allowlist | mitigate | Enforce REG-02 and REG-03 with caller-aware policy so only `get_order`, `get_refund_case`, `get_ticket`, and `search_policy` can be investigator-allowed, per D-09. |
| T-07-05 | T | registry construction | mitigate | Fail fast when schemas or safety metadata are missing, or when `allowed_in_investigator=true` is paired with non-read/retrieval risk or side effects, per REG-05 and D-12. |
| T-07-06 | D | unsafe invocation path | mitigate | Return structured rejection results for unknown, disallowed, or schema-invalid requests without calling underlying adapters, preventing write/action tools from executing through the investigator path. |
</threat_model>
