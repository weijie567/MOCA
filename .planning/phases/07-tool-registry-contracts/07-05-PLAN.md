<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| adapter output -> ToolRegistry.invoke | Adapter return dicts are runtime data and must be validated before becoming prompt-facing `ToolExecutionResult`. |
| registry metadata -> caller policy | Tool metadata may be malformed or model-constructed; caller policy must validate risk and side effect before execution. |
| checkpointed state -> receive_request | LangGraph checkpointed state can carry stale dormant fields into a later turn unless reset explicitly. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-13 | T | `ToolOutput.status` | mitigate | Type status with `ToolResultStatus` and add a regression proving `status="pending"` returns `validation_error`, not success. |
| T-07-14 | D | `ToolRegistry.invoke` conversion path | mitigate | Catch `ValidationError`, `AttributeError`, and `TypeError` from output validation/result conversion and return structured `ToolExecutionResult(status="error")`. |
| T-07-15 | E | non-investigator caller policy | mitigate | Require `load_business_context` tools to have `side_effect in {"none", "read_only"}` and `retrieve_policy_evidence` tools to have `side_effect == "retrieval"` before adapters execute. |
| T-07-16 | I | dormant investigation state | mitigate | Reset `investigation_result`, `investigation_steps`, `investigation_trigger_reason`, and `investigation_path` to `None` in `receive_request` and prove checkpointed stale values are cleared. |
</threat_model>
