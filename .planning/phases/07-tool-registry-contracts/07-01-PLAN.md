<objective>
Establish the schema-first contract layer that every later Phase 7 change builds on.

Purpose: lock the typed metadata, invocation, and prompt-facing result contracts before adapters or registry orchestration are added.
Output: `src/agent/tools/contracts.py` with strict Pydantic models and `tests/agent/test_tools/test_tool_contracts.py` proving required metadata fields, strict literals, and prompt-facing field rejection.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| investigator prompt -> ToolRegistry.invoke contract | Untrusted tool name/input will eventually cross into typed registry contracts. |
| raw tool payload -> prompt-facing ToolExecutionResult | Internal tool data must not leak undeclared fields to future investigator prompts. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | T | `src/agent/tools/contracts.py` metadata model | mitigate | Require `name`, `description`, `input_schema`, `output_schema`, `risk_level`, `side_effect`, `allowed_in_investigator`, `when_to_use`, `required_identifiers`, and `result_summary_fields`; reject incomplete definitions per REG-01 and D-04/D-05. |
| T-07-02 | I | prompt-facing result contract | mitigate | Use Pydantic `extra="forbid"` on `ToolExecutionResult` and related prompt-facing models per D-06 so undeclared raw payload fields cannot be serialized into investigator-visible output. |
| T-07-03 | E | risk/side-effect literals | mitigate | Constrain `risk_level`, `side_effect`, `status`, and `error_code` with strict `Literal[...]` values so unsafe combinations fail validation before runtime. |
</threat_model>
