<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| runtime source tables -> manifest | Manifest claims must be checked against code/spec-derived source tables and golden cases. |
| dataset file -> coverage gate | Dataset/hash metadata can be stale or incomplete. |
| eval metrics -> release gate | Pooled or under-sampled metrics must not pass per-critical-class gates. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-01 | Spoofing / Elevation of Privilege | golden ordinary-chat approval cases | mitigate | Golden cases include approval-looking chat and assert no trusted approval decision path. |
| T-11-02 | Tampering | manifest models | mitigate | Pydantic `extra="forbid"` models reject extra trusted fields or malformed metadata. |
| T-11-03 | Tampering / Information Disclosure | missing-slot golden cases | mitigate | Golden cases and manifest verify missing-slot routes enter `clarification_gate`, not tools/actions. |
| T-11-04 | Elevation of Privilege | Wilson/M6 gate | mitigate | Per-class Wilson status precedence blocks low-confidence/high-risk false negatives and insufficient samples. |
| T-11-05 | Repudiation | manifest coverage claims | mitigate | `validate_intent_manifest` fails missing coverage, stale hashes, invalid exemptions, and unsupported claims. |
</threat_model>
