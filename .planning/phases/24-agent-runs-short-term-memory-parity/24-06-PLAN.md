<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| graph final state -> finalizer | LLM/tool-derived final state enters backend terminal persistence. |
| finalizer -> conversation/summaries/session memory | Durable short-term memory is written from safe committed inputs only. |
| finalizer -> SSE final_response | User-visible final response is emitted after required memory result exists. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-01 | Tampering/Repudiation | completed finalizer | mitigate | Finalizer uses Plan 24-04 idempotent helpers and duplicate stream tests verify no duplicate memory surfaces. |
| T-24-02 | Repudiation | SSE final_response ordering | mitigate | Router waits for explicit `memory_write_status` before final_response; failures are recorded as skipped/error/failed. |
| T-24-03 | Spoofing/Tampering | conversation IDs | mitigate | Finalizer uses trusted run/user/session identity, not user payload IDs. |
| T-24-04 | Information Disclosure | finalizer scoped persistence | mitigate | Conversation and session writes are scoped by tenant/user/thread/run. |
| T-24-05 | Elevation of Privilege/Tampering | assistant metadata, summary, memory_write | mitigate | Finalizer persists prompt-safe metadata only and forbids raw/private/authority/debug fields. |
| T-24-06 | Repudiation | completed-only gate | mitigate | Finalizer executes only for exact `completed` status with final response; non-completed statuses handled in Plan 24-07. |
</threat_model>
