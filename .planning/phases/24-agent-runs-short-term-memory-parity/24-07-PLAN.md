<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| graph terminal events -> router status handling | Graph outcomes decide run status but must not fabricate completed memory. |
| SSE duplicate client -> pending claim | Reopened streams cross into backend claim logic and must not re-run side effects. |
| terminal persistence -> timeline | UI-visible timeline must not claim memory completion early. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-01 | Tampering/Repudiation | duplicate SSE guard | mitigate | Duplicate streams return `RUN_ALREADY_STARTED` before graph/finalizer and tests verify row counts stay unchanged. |
| T-24-02 | Repudiation | finalizer result before final_response | mitigate | Ordering test from Plan 24-06 remains required and timeline statuses are explicit. |
| T-24-03 | Spoofing/Tampering | graph config | transfer | Trusted IDs are implemented in Plan 24-05; this plan preserves no duplicate execution. |
| T-24-04 | Information Disclosure | duplicate/failure scoped state | mitigate | Failure paths preserve existing tenant/run checks and add no new cross-scope reads. |
| T-24-05 | Elevation of Privilege/Tampering | memory authority | mitigate | Non-completed memory is not summarized into contextual prompt surfaces as if it were an answer. |
| T-24-06 | Repudiation | error/cancel/interrupted paths | mitigate | Exact status guards prevent false assistant messages, false rolling summaries, and false successful memory writes. |
</threat_model>
