## 0. 这份计划的底层逻辑（先读这段再执行）

你不是零基础转型。你的真实状态是：

1. **技术底子够**（通信硕士、Python、2023 年就做过完整 RAG + 评测、MOCA 栈 = Agent JD 最大公约数）。
2. **最大风险是带着"讲不清的 MOCA"在求职**——面试官追问 MOCA 最出彩的部分（审批状态机/replay/证据契约）时答不上，比没项目更糟。
3. **产品表达是 0**（无 PRD、无场景拆解、无竞品分析）。

所以 30 天的主线不是"学新东西"，而是：
**先给 MOCA 止血（能讲清、扛追问）→ 同步把产品表达从 0 补到能拿出手 → 把技术债（FastAPI/Docker AI 写的部分）亲手过一遍。**

每一天都挂在能力地图的 16 项能力上（A1-A7 产品侧，B1-B9 工程侧）。

### 每日 10 小时固定结构

| 时段 | 时长 | 做什么 |
|---|---:|---|
| 理论 | 1.25h | 官方文档 / 原始论文 / 高质量中文官方资料，压缩成"对 Builder 的设计启发" |
| 拆解 | 1.75h | 拆现成产品 / 开源项目 / MOCA 自身模块：用户、任务流、工具、指标、失败模式 |
| 实战 | 2.25h | 写代码 / 改 MOCA / 内化 / 跑评测——必留可运行或可复现产物 |
| 产出 | 1.75h | PRD / 场景树 / 评测集 / 架构图 / 复盘 —— 直接进作品集 |
| 沉淀 | 1.5h | 当天总结 + 面试表达稿（"今天这块以后面试怎么讲"） |
| 面试追问 | 1.5h | 先生成“大厂技术追问模拟器”候选题，再练熟今日 Top 5；每题必须绑定 MOCA 证据、当前边界和继续追问回答 |

> 自动化落地：每日任务规格里固定包含 `T6 interview`，产物为 `portfolio/daily/dayXX_interview_questions.md`。T6 必须先按“今日主题直连 / MOCA 项目深挖 / 底层工程 / 架构升级 / 模型与框架 / 高级识别题”生成候选题，再挑今日必须练熟的 Top 5。晚间审计会把缺失或不合格的追问作为 `MISSING/PARTIAL`，第二天自动 carryover。

## 第一周：双线并行 — MOCA 收尾(Codex) + 内化 7-13 + 启动场景树

> **MOCA 决策（已锁定）：** 停在 **Phase 15**。Phase 14（执行边界）+ 15（replay 契约）由 **Codex 主力推进**，你走双 AI 流程做设计把关/裁决/内化，**不逐行手写架构代码**。Phase 16/17 不做，作为"有设计但刻意 defer"的面试话术。
>
> **为什么这样安排：** Phase 1-13 已是可演示闭环，14+15 把 MOCA 推过 MVP 完成线（建议带证据→审批状态机→draft-only 执行边界→可重放审计），这是面试最值钱的故事；而推进它们正好是你"读懂并讲清 AI 写的代码"的内化素材。

**本周双线：**
- **线 A（后台，约占你 2-3h/天的把关时间）：** Codex 推 14+15，你按 `CLAUDE.md` 双 AI 铁律做 plan 把关 + 裁决 Codex 审核 + 轻量收尾复核。
- **线 B（你的主时间）：** 内化已完成的 Phase 7-13，启动产品表达。

**周目标：** ①MOCA 进入 Phase 14/15 推进中；②你能讲清 7-13 已建成的主干（agent 编排 / 审批状态机 / RAG+证据 / 会话记忆）；③场景树初稿落地。
**周末验收：** 对着自己手画的架构图讲 8-10 分钟 MOCA 主链路不卡壳 + 场景树初稿 + Phase 14 已在 Codex 推进中。
