## 2. 为什么需要具体文档

需要。原因有三个：

1. `interview_question_rules.md` 是执行规则，适合给每日生成器读取，但不适合记录来源和设计演进。
2. Claude session 是历史日志，不稳定、不方便日后查找，也不应该成为执行时的唯一依据。
3. A-F 分类不是普通 checklist，而是面试训练方法论，应当作为面试资产长期保存。

因此本文作为“同步记录 + 规则解释”，`daily/interview_question_rules.md` 作为“每日执行规则”，`scripts/study/start_day.py` 作为“自动生成入口”。

## 3. 正式规则：先候选题，再 Top 5

每日不要直接写 5 道题。正确流程是：

```text
今日主题
→ 生成 A-F 候选题
→ 每题绑定 MOCA / 证据 / 当前边界
→ 从候选题里挑今日必须练熟的 Top 5
→ 晚间审计判断是否有证据、是否是通用八股
```

## 4. A-F 候选题结构

### A. 今日主题直连题

生成 5 题，必须直接围绕今天主题。

例：如果今天是“审批状态机”，就问：

- 为什么高风险动作要进入审批？
- 审批结果如何防止被篡改？
- 如果审批后 action payload 被改了怎么办？
- 如果 Agent 卡在 pending 状态怎么办？
- 如果审批事件重复提交怎么办？

### B. MOCA 项目深挖题

生成 5 题，必须绑定 MOCA 项目，并追问：

- 你的项目里具体怎么做？
- 为什么这么做？
- 如果线上出问题怎么办？
- 有没有替代方案？
- 你如何验证它有效？

### C. 底层工程追问题

生成 5 题，从当天主题最相关的底层工程点里选：

- Redis / cache
- MySQL / index
- Kafka / message queue
- Elasticsearch / BM25
- RAG retrieval
- context window
- tool calling
- trace / eval / risk
- error handling
- idempotency
- state machine
- fallback
- observability

### D. 架构升级题

生成 3 题，考察能否从 demo 讲到生产：

- 当前架构瓶颈在哪里？
- 用户量 / 工具量 / 知识库规模上来后怎么升级？
- 哪些地方必须从同步改异步？
- 哪些地方需要缓存？
- 哪些地方需要消息队列？
- 哪些地方必须人工审批？

### E. 模型与框架题

生成 3 题，考察模型、框架和协议边界：

- 为什么选 LangGraph / LangChain / OpenAI / Claude / Qwen？
- function calling / MCP / A2A / skills 怎么区分？
- ReAct / workflow / agent 怎么区分？
- prompt engineering / context engineering / harness engineering 怎么区分？

如果当天主题不相关，只做轻量回答，不展开成主线。

### F. 高级识别题

生成 2 题，只要求“能识别、能 60 秒简答”，不作为主攻：

- Agentic CPT / SFT / RL
- Observation token
- multi-agent communication
- Tree of Thought
- 多模态大模型
- 模型训练流程

## 5. 每题必填字段

每个候选题都必须包含：

1. 面试问题
2. 面试官想考什么
3. 60 秒回答要点
4. 如何绑定 MOCA
5. 我当前最可能卡住的点
6. 今天应该补的产物或证据

Top 5 还必须额外包含：

- 标准回答骨架
- MOCA 项目例子
- 一句面试金句
- 被继续追问时的 fallback 回答
- 状态：`READY / PARTIAL / NEEDS_MOCA_BINDING / NOT_STARTED`

## 6. few-shot 题型种子

这些是 Claude session 中确认过的真实技术追问风格，不要求每天全覆盖，但应作为题型池：

- ReAct 框架用过吗？消息格式是如何设计的？
- `tool_response` 应该用什么 role 传回？为什么？
- Redis 在 AI Agent 系统里有什么运用场景？如何设计缓存策略？
- MySQL 索引在什么情况下会失效？`LIKE` 查询什么时候走不了索引？
- 消息队列在 AI Agent 系统中有什么作用？为什么不直接通过数据库通信？
- RAG 为什么要引入父子索引？BM25 和向量检索如何融合？
- Agent 的短期记忆和长期记忆如何设计？上下文超限怎么处理？
- 工具库有上百个工具时，如何让模型快速准确选择？
- 工具调用失败怎么处理？
- 长上下文中如何不忘记关键信息，除了向量检索还有什么方法？
- Agent 决策出错导致误删数据，系统设计上如何防？
- 用户需求模糊，例如“按老样子处理一下”，Agent 如何处理？
- Kafka 在 AI Agent 系统里能用于什么场景？如何保证消息顺序？
- Elasticsearch 在 RAG 中起什么作用？如何优化检索性能？
- tools / workflow / agent 的本质区别是什么？
- function calling / A2A / MCP / skills 的区别是什么？
- prompt engineering / context engineering / harness engineering 有什么区别？
- multi-agent 架构如何设计？Agent 之间如何通信？
- 做 Agent 项目时，如何决定用什么模型和框架？
- 业务复杂后架构如何升级？现在架构顶得住吗？
- Agentic CPT / SFT / RL 三个阶段训练流程分别是什么？
- 为什么 SFT 时需要 Observation token？

## 7. 题型比例

每日题库不要平均用力，按下面比例控制：

| 类型 | 比例 | 目标 |
|---|---:|---|
| MOCA 项目深挖 | 40% | 必须能答深 |
| Agent / RAG / 工具调用 | 25% | 必须能结合项目答 |
| 工程底层 Redis / MySQL / MQ / ES | 20% | 能讲生产用法，不装资深后端 |
| 模型训练 / 多模态 / 多 Agent | 10% | 能识别、能简答、会边界 |
| 纯产品题 | 5% | 用来补 PM 表达 |
